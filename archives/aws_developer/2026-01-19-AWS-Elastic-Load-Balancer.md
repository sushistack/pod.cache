### 로드 밸런서란?

로드 밸런서는 서버 또는 서버 세트로, 수신된 트래픽을 여러 백엔드 또는 다운스트림 EC2 인스턴스(서버)로 전달하는 역할을 합니다.

### 로드 밸런싱의 핵심 이점

- 트래픽 분산: 여러 다운스트림 인스턴스에 부하를 분산하여 개별 인스턴스의 과부하를 방지합니다.
- 단일 액세스 지점 노출: 애플리케이션에 대한 단일 액세스 지점(DNS 이름)을 제공하여 사용자가 복잡한 백엔드 구조를 알 필요 없게 합니다.
- 장애 처리: 다운스트림 인스턴스의 장애를 자동으로 감지하고, 비정상 인스턴스로 트래픽 전송을 중단하여 애플리케이션의 연속성을 보장합니다.
- 상태 확인(Health Checks): 인스턴스의 상태를 지속적으로 확인하여 트래픽을 보낼 수 있는 건강한 인스턴스만 식별합니다.
- SSL/TLS 종료: HTTPS 암호화 트래픽을 로드 밸런서에서 종료하여 백엔드 인스턴스의 부하를 줄이고 보안을 강화할 수 있습니다.
- 세션 고정(Stickiness): 특정 사용자의 요청을 항상 동일한 백엔드 인스턴스로 보내야 하는 경우(예: 세션 정보 유지), 쿠키를 사용하여 세션을 고정할 수 있습니다.
- 고가용성: 여러 가용 영역(Availability Zone)에 걸쳐 인스턴스를 배포하고 로드 밸런싱하여 높은 가용성을 제공합니다.
- 트래픽 분리: 클라우드에서 퍼블릭 트래픽과 프라이빗 트래픽을 분리하여 관리할 수 있습니다.

### AWS Elastic Load Balancer (ELB)의 특징

- 관리형 서비스
- 비용 효율성 및 운영 편의성
- 다양한 AWS 서비스와의 통합

### AWS ELB의 다양한 종류

- Classic Load Balancer
- Application Load Balancer
- Network Load Balancer
- Gateway Load Balancer

#### 내부(Internal) 및 외부(External) 로드 밸런서

로드 밸런서는 네트워크 구성에 따라 내부(프라이빗 액세스) 또는 외부(퍼블릭 액세스)로 설정할 수 있습니다. 웹사이트와 같은 공용 애플리케이션에는 외부 로드 밸런서가, 내부 서비스에는 내부 로드 밸런서가 사용됩니다.


### 헬스 체크 작동 방식

로드 밸런서는 지정된 프로토콜, 포트, 경로(엔드포인트)를 사용하여 인스턴스의 상태를 확인합니다. 예를 들어, `HTTP` 프로토콜의 `4567` 포트에 `/health` 엔드포인트로 요청을 보낼 수 있습니다.

### 로드 밸런서 보안 그룹

사용자는 HTTP(80 포트) 또는 HTTPS(443 포트)를 사용하여 로드 밸런서에 접속합니다. 따라서 로드 밸런서의 보안 그룹은 모든 IP 주소(`0.0.0.0/0`)로부터 이러한 포트에 대한 인바운드 트래픽을 허용해야 합니다.


### EC2 인스턴스 보안 그룹

EC2 인스턴스는 오직 로드 밸런서로부터 오는 트래픽만 허용해야 합니다.
