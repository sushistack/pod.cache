# 048. 🚀 001. EBS Multi-Attach: 다중 EC2 인스턴스를 위한 공유 스토리지 혁신

## 요약
*   EBS Multi-Attach는 하나의 io1 또는 io2 볼륨을 동일한 가용 영역 내 여러 EC2 인스턴스에 동시 연결하는 기능입니다.
*   각 인스턴스는 볼륨에 대한 완전한 읽기/쓰기 권한을 가지며, 최대 16개의 인스턴스 연결을 지원합니다.
*   고가용성 클러스터링 애플리케이션 및 동시 쓰기 관리가 필요한 시나리오에서 데이터 접근성과 복원력을 향상시킵니다.

---

## 서론

클라우드 환경에서 고가용성(High Availability)과 데이터 공유는 애플리케이션의 안정성과 성능을 보장하는 핵심 요소입니다. AWS Elastic Block Store (EBS)는 EC2 인스턴스에 지속적인 블록 스토리지를 제공하는 서비스로, 오랫동안 단일 EBS 볼륨은 하나의 EC2 인스턴스에만 연결될 수 있었습니다. 이러한 제약은 공유 스토리지를 필요로 하는 클러스터링 환경에서 특정 아키텍처적 도전을 야기했습니다.

하지만 AWS EBS Multi-Attach 기능의 도입으로 이러한 제한이 해소되었습니다. 이제 하나의 고성능 EBS 볼륨을 여러 EC2 인스턴스에 동시에 연결하여, 고가용성 및 데이터 공유 시나리오를 더욱 효율적으로 구현할 수 있게 되었습니다. 이번 글에서는 EBS Multi-Attach 기능이 무엇이며, 어떤 특징과 이점을 제공하는지, 그리고 개발자들이 이 기능을 어떻게 활용할 수 있는지 상세히 알아보겠습니다.

## 본론

### EBS Multi-Attach란 무엇인가요?

EBS Multi-Attach는 이름 그대로 하나의 EBS 볼륨을 **동일한 가용 영역(Availability Zone) 내의 여러 EC2 인스턴스에 동시에 연결**할 수 있도록 하는 기능입니다. 기존에는 EBS 볼륨이 특정 EC2 인스턴스에 종속되어 있었지만, Multi-Attach를 통해 여러 인스턴스가 동일한 고성능 블록 스토리지에 접근하고 데이터를 공유할 수 있게 된 것입니다.

이 기능은 특히 다음과 같은 고성능 볼륨 유형에서 지원됩니다.

*   `io1` (Provisioned IOPS SSD)
*   `io2` (Provisioned IOPS SSD)

Multi-Attach가 활성화된 볼륨은 연결된 각 EC2 인스턴스에 대해 **완전한 읽기 및 쓰기 권한**을 제공합니다. 이는 여러 인스턴스가 동시에 볼륨에 데이터를 쓰고 읽을 수 있음을 의미하며, 복잡한 클러스터 환경에서 데이터 일관성과 가용성을 유지하는 데 중요한 역할을 합니다.

### 주요 특징 및 고려사항

EBS Multi-Attach를 효과적으로 사용하기 위해서는 그 특징과 제한사항을 명확히 이해하는 것이 중요합니다.

#### 1. 지원되는 볼륨 유형

Multi-Attach는 AWS의 고성능 Provisioned IOPS SSD 볼륨인 `io1`과 `io2`에서만 지원됩니다. 이는 Multi-Attach의 주된 사용 사례가 높은 성능과 낮은 지연 시간을 요구하는 엔터프라이즈급 애플리케이션에 집중되어 있음을 시사합니다.

```
# EBS Multi-Attach 지원 볼륨 유형
- io1 (Provisioned IOPS SSD)
- io2 (Provisioned IOPS SSD)
```

#### 2. 가용 영역(Availability Zone) 제한

가장 중요한 제한 사항 중 하나는 Multi-Attach가 **동일한 가용 영역(AZ) 내에서만 작동한다**는 점입니다. 다른 AZ에 있는 EC2 인스턴스에는 Multi-Attach 볼륨을 연결할 수 없습니다. 이는 EBS가 AZ 내에서 강력한 일관성을 보장하기 위한 아키텍처적 선택입니다. 따라서 Multi-Attach를 사용하는 시스템은 단일 AZ 내에서 고가용성을 확보해야 합니다.

#### 3. 연결 가능한 인스턴스 수

하나의 EBS Multi-Attach 볼륨에 동시에 연결할 수 있는 EC2 인스턴스의 수는 **최대 16개**로 제한됩니다. 이 숫자는 시험에서도 종종 언급될 수 있으므로 기억해 두는 것이 좋습니다.

```
# 최대 연결 인스턴스 수
16개 EC2 인스턴스
```

#### 4. 파일 시스템 요구사항

Multi-Attach 볼륨을 여러 인스턴스에서 안전하게 사용하려면 **클러스터 인식 파일 시스템(Cluster-aware File System)**이 필수적입니다. 일반적인 단일 호스트 파일 시스템(예: XFS, EXT4)은 여러 호스트가 동시에 쓰기 작업을 수행할 때 데이터 손상이나 일관성 문제를 일으킬 수 있습니다. 따라서 OCFS2 (Oracle Cluster File System 2) 또는 GFS2 (Global File System 2)와 같은 클러스터 파일 시스템을 사용해야 합니다. 이러한 파일 시스템은 여러 노드 간의 동시 접근 및 잠금 메커니즘을 관리하여 데이터 무결성을 보장합니다.

### EBS Multi-Attach 활용 사례

EBS Multi-Attach는 특정 유형의 고가용성 및 성능 요구사항을 가진 애플리케이션에 특히 유용합니다.

#### 1. 고가용성 클러스터링 애플리케이션

가장 대표적인 활용 사례는 **클러스터링된 리눅스 애플리케이션의 고가용성 확보**입니다. 예를 들어, `Teradata`와 같은 대규모 데이터베이스 시스템이나 공유 디스크 클러스터를 사용하는 애플리케이션은 Multi-Attach를 통해 데이터 저장소의 SPOF(Single Point of Failure)를 제거할 수 있습니다.

**시나리오:**
*   클러스터의 한 인스턴스에 장애가 발생하더라도, 다른 인스턴스가 동일한 EBS 볼륨에 즉시 접근하여 작업을 인계받을 수 있습니다.
*   이는 애플리케이션 다운타임을 최소화하고 서비스 연속성을 크게 향상시킵니다.

#### 2. 동시 쓰기 작업 관리

여러 인스턴스가 동일한 데이터에 대해 **동시 읽기/쓰기 작업을 수행**해야 하는 시나리오에서도 Multi-Attach가 유용합니다.

**시나리오:**
*   공유 캐시, 분산 큐 또는 특정 공유 로그 파일과 같이 여러 워커 인스턴스가 동일한 데이터 블록에 접근해야 할 때 사용될 수 있습니다.
*   물론, 이 경우에도 애플리케이션 레벨에서 데이터 동시성 및 일관성 제어 로직(예: 분산 락)이 강력하게 구현되어야 합니다. Multi-Attach 자체는 파일 시스템 레벨의 동시성 문제를 해결해 줄 뿐, 애플리케이션 데이터의 논리적 일관성까지 보장하지는 않습니다.

## 결론

EBS Multi-Attach 기능은 AWS 클라우드 환경에서 고성능 `io1` 및 `io2` 볼륨의 잠재력을 극대화하여 고가용성 및 데이터 공유 아키텍처를 구현하는 강력한 도구입니다. 이 기능을 통해 개발자들은 더욱 견고하고 유연한 클러스터링 솔루션을 설계할 수 있게 되었습니다.

물론, Multi-Attach는 동일한 가용 영역 내에서만 작동하며, 최대 16개의 인스턴스 연결 제한, 그리고 클러스터 인식 파일 시스템 요구사항과 같은 고려사항이 있습니다. 이러한 제약 사항들을 명확히 이해하고 적절한 아키텍처 설계를 통해, Multi-Attach는 복잡한 엔터프라이즈 워크로드의 가용성과 성능을 한 단계 끌어올리는 데 크게 기여할 것입니다. 개발자들이 이 강력한 기능을 효과적으로 활용하여 더욱 안정적이고 효율적인 클라우드 애플리케이션을 구축하기를 바랍니다.
