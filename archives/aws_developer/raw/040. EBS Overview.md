# 040. 🚀 EC2 스토리지의 핵심, EBS 완전 정복

AWS EC2 인스턴스의 안정적인 데이터 관리는 서비스 운영에 있어 매우 중요합니다. 이 글에서는 EC2 인스턴스를 위한 핵심 스토리지 옵션인 EBS(Elastic Block Store) 볼륨의 모든 것을 다룹니다. EBS 볼륨의 기본 개념부터 아키텍처, 사용 시나리오 및 주요 설정까지, 개발자들이 반드시 알아야 할 유용한 정보를 제공합니다.

### 💡 핵심 요약
*   `EBS (Elastic Block Store)`는 EC2 인스턴스에 네트워크를 통해 연결되는 영구 블록 스토리지입니다.
*   데이터 영속성을 보장하며, 특정 가용 영역(AZ)에 종속되고 한 번에 하나의 인스턴스에만 부착될 수 있습니다.
*   `Delete on Termination` 속성을 통해 인스턴스 종료 시 EBS 볼륨의 보존 여부를 제어할 수 있습니다.

---

## 서론: EC2 인스턴스와 영구 스토리지의 필요성

클라우드 컴퓨팅 환경에서 AWS EC2(Elastic Compute Cloud) 인스턴스는 다양한 애플리케이션을 구동하는 데 필수적인 가상 서버입니다. EC2 인스턴스는 컴퓨팅 리소스를 제공하지만, 인스턴스가 종료되면 내부에 저장된 데이터는 사라질 수 있습니다. 이러한 휘발성 문제를 해결하고 데이터의 영속성을 보장하기 위해 AWS는 `EBS (Elastic Block Store)`라는 전용 블록 스토리지 서비스를 제공합니다.

EBS 볼륨은 EC2 인스턴스와 별개로 생성 및 관리되며, 네트워크를 통해 인스턴스에 부착되어 사용됩니다. 마치 물리적인 서버에 USB 드라이브를 연결하는 것처럼, EC2 인스턴스에 데이터를 저장하고 필요에 따라 다른 인스턴스로 옮겨 사용할 수 있는 유연성을 제공합니다. 이 아티클에서는 EBS 볼륨의 주요 특징과 활용 방법을 심층적으로 살펴보겠습니다.

## 본론: EBS 볼륨의 이해와 활용

### 1. EBS란 무엇인가?

EBS는 EC2 인스턴스를 위한 고성능 블록 스토리지 서비스입니다. 여기서 '블록 스토리지'란 데이터를 고정된 크기의 블록 단위로 저장하고 관리하는 방식을 의미하며, 운영체제 수준에서 디스크 드라이브처럼 인식됩니다.

*   **네트워크 드라이브**: EBS 볼륨은 물리적으로 인스턴스에 연결되는 것이 아니라, 네트워크를 통해 연결됩니다. 이로 인해 유연한 부착 및 분리, 그리고 고가용성을 확보할 수 있습니다.
*   **데이터 영속성**: EC2 인스턴스가 종료되더라도 EBS 볼륨에 저장된 데이터는 유지됩니다. 이는 새로운 인스턴스를 시작하고 기존 EBS 볼륨을 부착하여 데이터를 쉽게 복구할 수 있음을 의미합니다.
*   **가용 영역(AZ) 종속성**: EBS 볼륨은 생성된 특정 가용 영역(예: `us-east-1a`)에 묶입니다. 따라서 다른 가용 영역(`us-east-1b`)에 있는 EC2 인스턴스에는 직접 부착할 수 없습니다. 이 제약은 스냅샷 기능을 통해 해결될 수 있습니다.

### 2. EBS 볼륨의 아키텍처 및 동작 방식

EBS 볼륨은 EC2 인스턴스와 네트워크 통신을 통해 데이터를 주고받습니다. 이 방식은 몇 가지 중요한 특성을 가집니다.

*   **네트워크 기반 통신**: 인스턴스와 EBS 볼륨 간의 데이터 전송은 네트워크를 통해 이루어지므로, 미세한 지연 시간(latency)이 발생할 수 있습니다. 하지만 AWS의 최적화된 네트워크 인프라 덕분에 대부분의 워크로드에서 충분히 낮은 지연 시간을 보장합니다.
*   **빠른 탈착 및 부착**: EBS 볼륨은 실행 중인 EC2 인스턴스에서 분리하여 다른 인스턴스에 신속하게 부착할 수 있습니다. 이 기능은 특히 장애 조치(failover) 상황에서 매우 유용하며, 서비스의 연속성을 유지하는 데 기여합니다.
*   **가용 영역(AZ) 고정**:
    *   `EBS 볼륨은 특정 가용 영역에 생성되면 해당 AZ 내에서만 사용 가능합니다.`
    *   예를 들어, `us-east-1a`에 생성된 EBS 볼륨은 `us-east-1a` 내의 EC2 인스턴스에만 부착될 수 있습니다.
    *   **스냅샷을 통한 AZ 간 이동**: EBS 스냅샷을 생성하면 볼륨의 데이터를 백업하고, 이 스냅샷을 사용하여 다른 가용 영역이나 다른 리전에서 새로운 EBS 볼륨을 생성할 수 있습니다.

### 3. EBS 볼륨 프로비저닝 및 과금

EBS 볼륨은 사용자가 직접 용량과 성능을 사전에 정의(provision)해야 합니다.

*   **용량 프로비저닝**: 볼륨 생성 시 필요한 기가바이트(GB) 단위를 미리 설정해야 합니다.
*   **IOPS (Input/Output Operations Per Second) 프로비저닝**: 볼륨의 성능을 나타내는 지표인 IOPS 또한 사전에 지정할 수 있습니다. 높은 IOPS는 더 빠른 데이터 처리 속도를 의미합니다.
*   **과금 방식**: 사용자는 프로비저닝된 용량과 IOPS에 대해 요금을 지불합니다. 필요에 따라 언제든지 용량이나 성능을 증설할 수 있습니다.

### 4. EBS 부착 시나리오

EBS 볼륨은 다양한 방식으로 EC2 인스턴스에 부착될 수 있습니다.

*   **단일 인스턴스 부착**: AWS Certified Cloud Practitioner 레벨에서는 하나의 EBS 볼륨이 한 번에 하나의 EC2 인스턴스에만 부착될 수 있다고 설명됩니다.
    *   ```
        [EC2 Instance A (us-east-1a)] <--- Attached to ---> [EBS Volume 1 (us-east-1a)]
        ```
*   **다중 EBS 볼륨 부착**: 하나의 EC2 인스턴스에는 여러 개의 EBS 볼륨을 부착할 수 있습니다. 이는 마치 하나의 컴퓨터에 여러 개의 USB 드라이브를 연결하는 것과 같습니다.
    *   ```
        [EBS Volume 1 (us-east-1a)]
                    ^
                    |
        [EC2 Instance A (us-east-1a)]
                    |
                    v
        [EBS Volume 2 (us-east-1a)]
        ```
*   **분리된 EBS 볼륨**: EBS 볼륨은 EC2 인스턴스에 부착되지 않고 독립적으로 존재할 수 있으며, 필요할 때 언제든지 특정 인스턴스에 부착할 수 있습니다.

### 5. 인스턴스 종료 시 EBS 볼륨 보존 여부 제어: Delete on Termination

EC2 인스턴스를 생성할 때 EBS 볼륨에 대한 `Delete on Termination`이라는 중요한 속성을 설정할 수 있습니다. 이 속성은 인스턴스 종료 시 해당 EBS 볼륨의 운명을 결정합니다.

*   **기본 동작**:
    *   **루트 볼륨 (Root Volume)**: 운영체제가 설치된 기본 볼륨은 `Delete on Termination`이 **기본적으로 활성화**되어 있습니다. 즉, EC2 인스턴스가 종료되면 루트 볼륨도 함께 삭제됩니다.
    *   **추가(Non-Root) EBS 볼륨**: 사용자가 직접 추가한 데이터 볼륨은 `Delete on Termination`이 **기본적으로 비활성화**되어 있습니다. 따라서 인스턴스가 종료되어도 해당 볼륨은 삭제되지 않고 보존됩니다.

*   **설정 변경 및 활용**:
    이 속성은 AWS 콘솔이나 AWS CLI를 통해 언제든지 변경할 수 있습니다.
    *   **루트 볼륨 보존**: 만약 인스턴스 종료 시에도 루트 볼륨에 저장된 데이터를 보존하고 싶다면, `Delete on Termination` 속성을 **비활성화**할 수 있습니다. 이는 특정 설정이나 로그 데이터를 인스턴스 재시작(termination 후 재생성) 시에도 유지해야 할 때 유용합니다.
    *   **추가 볼륨 삭제**: 반대로, 추가 볼륨이 인스턴스와 함께 자동으로 삭제되기를 원한다면, 해당 속성을 **활성화**할 수 있습니다.

이 `Delete on Termination` 속성은 시험 문제에서 자주 다루어질 수 있는 중요한 개념이므로, 각 볼륨 유형에 따른 기본 동작과 이를 변경했을 때의 효과를 명확히 이해하는 것이 중요합니다.

## 결론: EBS 볼륨, EC2의 강력한 파트너

EBS 볼륨은 AWS EC2 인스턴스 환경에서 데이터 영속성, 유연성 및 성능을 제공하는 핵심 스토리지 서비스입니다. 네트워크 드라이브로서의 특성, 가용 영역 종속성, 용량 및 성능 프로비저닝, 그리고 `Delete on Termination`과 같은 세부 설정은 EC2 기반 애플리케이션의 안정성과 효율성을 결정하는 중요한 요소들입니다.

개발자는 EBS의 이러한 특성들을 정확히 이해하고 적절히 활용함으로써, 데이터 손실 위험을 줄이고, 장애 발생 시 빠른 복구를 가능하게 하며, 전반적인 서비스 운영 안정성을 크게 향상시킬 수 있습니다. EBS는 단순한 저장 공간을 넘어, 클라우드 아키텍처 설계에서 없어서는 안 될 강력한 파트너입니다.
