# 037. 💻 SSH 키 없이 브라우저에서 EC2 접속: EC2 Instance Connect 완벽 활용 가이드

AWS EC2 Instance Connect는 SSH 키 관리의 번거로움 없이 웹 브라우저를 통해 EC2 인스턴스에 안전하게 접속할 수 있는 서비스입니다. 임시 SSH 키 업로드 방식을 사용하여 연결되며, 별도의 SSH 클라이언트 설정 없이 즉시 터미널 환경을 제공합니다. 다만, 내부적으로 SSH(Port 22) 프로토콜을 사용하므로, EC2 보안 그룹에서 해당 포트가 열려 있어야 정상적인 접속이 가능합니다.

---

## 🚀 서론: SSH 번거로움, 이제 그만!

클라우드 환경에서 가상 서버인 AWS EC2 인스턴스에 접속하는 것은 개발자에게 매우 흔한 작업입니다. 전통적으로 SSH(Secure Shell) 클라이언트를 사용하여 접속했지만, 이 방식은 SSH 키 페어 생성, `.pem` 파일 관리, 권한 설정, 터미널 명령어 입력 등 여러 단계를 거쳐야 하는 번거로움이 있었습니다. 특히 여러 인스턴스를 관리하거나 급하게 접속해야 할 때 이러한 과정은 비효율적일 수 있습니다.

이러한 불편함을 해소하기 위해 AWS는 `EC2 Instance Connect`라는 편리한 대안을 제공합니다. 이 아티클에서는 EC2 Instance Connect가 무엇인지, 어떻게 사용하는지, 그리고 잠재적인 문제 발생 시 해결 방법까지 상세히 알아보겠습니다.

## ✨ 본론: EC2 Instance Connect, 어떻게 동작하고 활용할까?

### 1. EC2 Instance Connect란 무엇인가?

EC2 Instance Connect는 웹 브라우저 기반으로 EC2 인스턴스에 SSH 세션을 설정할 수 있게 해주는 AWS 서비스입니다. 가장 큰 특징은 **SSH 키 파일을 직접 관리할 필요가 없다**는 점입니다. 접속 시 AWS가 임시 SSH 키를 자동으로 생성하여 인스턴스에 업로드하고 연결을 설정하므로, 사용자는 오직 브라우저만으로 SSH 세션을 시작할 수 있습니다.

**주요 장점:**

*   **키 관리 불필요**: SSH 키 페어를 생성하거나 로컬에 저장할 필요가 없습니다.
*   **브라우저 기반**: 별도의 SSH 클라이언트(PuTTY, Terminal 등) 설치 없이 웹 브라우저에서 즉시 접속 가능합니다.
*   **간편한 접근**: AWS 콘솔에서 몇 번의 클릭만으로 SSH 세션 시작이 가능합니다.
*   **보안 강화**: 임시 키 사용으로 장기 키 유출 위험을 줄일 수 있습니다.

### 2. EC2 Instance Connect 사용 방법

EC2 Instance Connect를 사용하여 인스턴스에 접속하는 과정은 매우 직관적입니다.

1.  **EC2 인스턴스 선택**: AWS Management Console에서 EC2 서비스로 이동하여 접속하려는 인스턴스를 선택합니다.
2.  **'연결(Connect)' 버튼 클릭**: 인스턴스 상세 정보 페이지 상단에 있는 '연결(Connect)' 버튼을 클릭합니다.
3.  **'EC2 Instance Connect' 탭 선택**: 여러 연결 옵션 중 'EC2 Instance Connect' 탭을 선택합니다.
4.  **사용자 이름 확인**: 기본 사용자 이름은 인스턴스의 OS 종류에 따라 자동 설정됩니다. Amazon Linux 2 AMI의 경우 `ec2-user`가 기본값입니다. 필요하다면 변경할 수 있지만, 대부분 `ec2-user`를 사용해야 합니다.
5.  **'연결(Connect)' 클릭**: 모든 설정이 올바른지 확인한 후 '연결(Connect)' 버튼을 클릭하면, 새 브라우저 탭에서 SSH 세션이 시작됩니다.

```bash
# 접속 후 기본 명령어 실행 예시
whoami
# 출력: ec2-user

ping google.com
# Google 서버로의 연결 테스트
```

### 3. EC2 Instance Connect의 내부 동작 및 보안 그룹 설정의 중요성

EC2 Instance Connect가 SSH 키 관리를 대신해주고 브라우저를 통해 접속하지만, 여전히 내부적으로는 **SSH 프로토콜(Port 22)**을 사용하여 인스턴스와 통신합니다. 따라서 인스턴스의 보안 그룹(Security Group)에서 Port 22가 열려 있어야만 정상적인 연결이 가능합니다.

만약 보안 그룹 설정이 잘못되어 Port 22가 차단되어 있다면, EC2 Instance Connect는 연결에 실패합니다.

**문제 상황 시연:**

강의에서는 다음 과정을 통해 보안 그룹의 중요성을 보여줍니다.

1.  EC2 인스턴스의 보안 그룹에서 SSH(Port 22) 인바운드 규칙을 삭제합니다.
2.  EC2 Instance Connect를 통해 접속을 시도하면, `problem connecting to your Instance`와 같은 오류 메시지와 함께 연결이 실패합니다.

**해결책: 보안 그룹 규칙 수정**

EC2 Instance Connect를 성공적으로 사용하려면, 인스턴스의 보안 그룹에 SSH(Port 22) 인바운드 규칙을 추가해야 합니다.

1.  EC2 인스턴스 상세 페이지에서 연결된 보안 그룹을 클릭합니다.
2.  '인바운드 규칙(Inbound Rules)' 탭에서 '인바운드 규칙 편집(Edit inbound rules)'을 클릭합니다.
3.  **새 규칙 추가**:
    *   **유형**: `SSH`
    *   **포트 범위**: `22`
    *   **소스**:
        *   `Anywhere-IPv4 (0.0.0.0/0)`를 추가합니다.
        *   환경에 따라 `Anywhere-IPv6 (::/0)`도 추가해야 할 수 있습니다.
        *   특정 IP 주소에서만 접속하도록 제한하려면 `내 IP` 또는 사용자 지정 IP 범위를 지정할 수 있습니다.
4.  '규칙 저장(Save rules)'을 클릭하여 변경 사항을 적용합니다.

**보안 그룹 규칙 예시:**

```
| 유형 | 프로토콜 | 포트 범위 | 소스 |
|---|---|---|---|
| SSH | TCP | 22 | 0.0.0.0/0 |
| SSH | TCP | 22 | ::/0 |
```

이 규칙이 추가되면 EC2 Instance Connect를 통해 다시 인스턴스에 성공적으로 접속할 수 있습니다.

## 🏁 결론: 간편함과 보안을 동시에!

EC2 Instance Connect는 AWS EC2 인스턴스에 접속하는 과정을 혁신적으로 간소화하여 개발자의 생산성을 크게 향상시킵니다. 특히 SSH 키 관리의 부담 없이 브라우저에서 즉시 터미널 세션을 시작할 수 있다는 점은 매우 큰 장점입니다.

하지만 이 서비스가 내부적으로 SSH 프로토콜에 의존한다는 점을 이해하고, 보안 그룹에서 Port 22가 올바르게 설정되어 있는지 항상 확인하는 것이 중요합니다. EC2 Instance Connect는 일상적인 인스턴스 관리나 빠른 디버깅이 필요할 때 매우 유용한 도구이며, AWS 클라우드 환경에서 작업하는 모든 개발자에게 강력히 추천합니다.
