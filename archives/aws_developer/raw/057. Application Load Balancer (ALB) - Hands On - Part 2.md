# 057. 🔒 AWS 로드 밸런서: EC2 보안 강화 및 고급 트래픽 라우팅 전략

---

클라우드 환경에서 애플리케이션의 가용성과 확장성을 높이는 데 필수적인 로드 밸런서는 단순한 트래픽 분배를 넘어, 보안과 유연한 트래픽 제어의 핵심 요소로 자리 잡고 있습니다. 이 아티클에서는 AWS Application Load Balancer(ALB)를 활용하여 EC2 인스턴스의 네트워크 보안을 강화하고, 경로 기반 라우팅을 포함한 고급 트래픽 관리 규칙을 설정하는 방법을 상세히 다룹니다.

**핵심 요약:**
*   로드 밸런서와 연동된 EC2 인스턴스의 네트워크 보안을 강화하기 위해 EC2 보안 그룹의 인바운드 규칙을 조정합니다.
*   ALB 리스너 규칙을 활용하여 요청의 특정 조건(예: 경로, 호스트 헤더)에 따라 트래픽을 유연하게 처리합니다.
*   경로 기반 고정 응답 반환 기능을 구현하여 특정 URL 패턴에 대한 커스텀 에러 페이지를 제공함으로써 사용자 경험을 향상할 수 있습니다.

---

## 서론: 로드 밸런서의 고급 활용을 통한 인프라 최적화

클라우드 기반 애플리케이션에서 로드 밸런서는 여러 서버에 걸쳐 트래픽을 분산하여 성능을 최적화하고 단일 장애 지점을 제거하는 중요한 역할을 합니다. 특히 AWS의 Application Load Balancer(ALB)는 HTTP/HTTPS 트래픽에 특화되어 있으며, 레이어 7에서 작동하여 경로 기반 라우팅, 호스트 기반 라우팅 등 애플리케이션 수준의 고급 기능을 제공합니다.

이번 아티클에서는 이러한 로드 밸런서의 잠재력을 최대한 활용하여 EC2 인스턴스의 보안을 한층 강화하고, ALB의 리스너 규칙을 통해 복잡한 트래픽 흐름을 효과적으로 제어하는 방법을 집중적으로 탐구합니다. 이는 애플리케이션의 안정성과 보안성을 높이는 동시에, 사용자에게 더욱 유연하고 개선된 서비스를 제공하는 데 기여할 것입니다.

## 본론 1: EC2 인스턴스에 대한 네트워크 보안 강화 전략

로드 밸런서를 사용하는 주요 목적 중 하나는 백엔드 EC2 인스턴스를 외부 위협으로부터 보호하는 것입니다. 하지만 기본 설정에서는 EC2 인스턴스가 여전히 퍼블릭 IP를 통해 직접 접근될 수 있는 경우가 많아 보안상 취약점이 될 수 있습니다. 로드 밸런서를 통해서만 EC2 인스턴스에 접근하도록 제한하는 방법은 다음과 같습니다.

### 현재 보안 설정의 문제점 진단

초기 설정에서 EC2 인스턴스의 보안 그룹은 보통 모든 IP 주소(`0.0.0.0/0`)로부터 특정 포트(예: HTTP 80)로의 인바운드 트래픽을 허용합니다. 이 경우, 사용자는 로드 밸런서를 통해서뿐만 아니라, EC2 인스턴스의 퍼블릭 IP를 직접 사용하여 접근할 수도 있습니다. 이는 로드 밸런서의 필터링 및 보안 기능을 우회할 수 있는 경로를 제공하여 잠재적인 보안 위험을 초래합니다.

### 로드 밸런서를 통한 EC2 접근 강제화

EC2 인스턴스에 대한 직접적인 접근을 차단하고 로드 밸런서를 통해서만 트래픽을 허용하려면, EC2 인스턴스의 보안 그룹 규칙을 수정해야 합니다. 핵심은 EC2 보안 그룹의 인바운드 규칙 소스를 *로드 밸런서의 보안 그룹*으로 지정하는 것입니다.

**EC2 보안 그룹 규칙 변경 단계:**

1.  **EC2 인스턴스의 보안 그룹 확인**: 접근을 제한하려는 EC2 인스턴스에 연결된 보안 그룹을 식별합니다. (예: `launch-wizard-1` 보안 그룹)
2.  **인바운드 규칙 편집**: 해당 보안 그룹의 인바운드 규칙 섹션으로 이동합니다.
3.  **기존 HTTP(S) 규칙 삭제**: 현재 `0.0.0.0/0` 또는 다른 광범위한 소스로부터의 HTTP(S) 트래픽을 허용하는 규칙을 삭제합니다.
4.  **새 규칙 추가**:
    *   **유형(Type)**: `HTTP` 또는 `HTTPS` (애플리케이션에 따라 선택)
    *   **소스(Source)**: 여기서 `Custom`을 선택한 후, 드롭다운 목록에서 **로드 밸런서의 보안 그룹**을 선택합니다. (예: `sg-xxxxxxxxxx (load-balancer-security-group)`)
5.  **규칙 저장**: 변경 사항을 저장합니다.

이러한 변경을 통해 EC2 인스턴스는 로드 밸런서 보안 그룹에서 오는 트래픽만을 허용하게 됩니다. 결과적으로 외부에서 EC2 인스턴스의 퍼블릭 IP로 직접 접근을 시도하면 타임아웃이 발생하며 접근이 거부됩니다. 반면, 로드 밸런서의 DNS 이름을 통해 접근하면 정상적으로 트래픽이 EC2 인스턴스로 전달됩니다.

**예시 - EC2 인스턴스 보안 그룹 규칙 (변경 후):**

```
Inbound rules:
| Type | Protocol | Port Range | Source                       | Description |
|------|----------|------------|------------------------------|-------------|
| HTTP | TCP      | 80         | sg-xxxxxxxxxx (ALB-SecurityGroup) | Allow HTTP traffic from ALB |
| SSH  | TCP      | 22         | Your_IP_Address/32           | Allow SSH access from your IP |
```

이 방식은 EC2 인스턴스를 로드 밸런서 뒤에 숨김으로써 네트워크 보안 태세를 크게 강화합니다.

## 본론 2: Application Load Balancer(ALB)의 고급 리스너 규칙 활용

ALB의 리스너 규칙은 들어오는 트래픽에 대한 조건을 정의하고, 해당 조건이 일치할 때 수행할 동작을 지정하는 강력한 기능입니다. 이를 통해 단일 로드 밸런서로 여러 애플리케이션을 호스팅하거나, 특정 트래픽에 대한 맞춤형 응답을 제공할 수 있습니다.

### 리스너 규칙의 기본 이해

ALB 리스너는 특정 포트에서 요청을 수신하며, 정의된 규칙에 따라 트래픽을 타겟 그룹으로 라우팅하거나 다른 동작을 수행합니다. 각 리스너에는 하나 이상의 규칙이 있으며, 이러한 규칙들은 우선순위에 따라 순서대로 평가됩니다.

*   **기본 규칙(Default Rule)**: 모든 요청에 대해 적용되는 최종 규칙입니다. 일반적으로 모든 트래픽을 특정 타겟 그룹으로 전달하도록 설정됩니다.
*   **사용자 정의 규칙**: 특정 조건이 만족될 때만 적용되는 규칙으로, 우선순위(Priority)를 가집니다.

### 고급 리스너 규칙 설정 방법

새로운 규칙을 추가하여 특정 경로(`Path`), 호스트 헤더(`Host header`), HTTP 메서드(`HTTP method`), 소스 IP(`Source IP`), 쿼리 문자열(`Query string`) 또는 HTTP 헤더(`HTTP header`)와 같은 다양한 조건을 기반으로 트래픽을 제어할 수 있습니다.

**예시 - `/error` 경로에 대한 고정 응답 규칙 설정:**

사용자가 웹사이트의 `/error` 경로로 접근할 경우, 서버가 아닌 로드 밸런서 수준에서 특정 에러 메시지를 반환하도록 설정할 수 있습니다.

1.  **ALB 선택 및 리스너 접근**: AWS 콘솔에서 해당 Application Load Balancer를 선택하고, `Listeners` 탭으로 이동합니다.
2.  **규칙 관리**: 리스너를 선택한 후 `View/edit rules`를 클릭합니다.
3.  **규칙 삽입**: `Insert Rule`을 선택하여 새로운 규칙을 생성합니다. (우선순위를 고려하여 적절한 위치에 삽입)
4.  **조건(Condition) 정의**:
    *   `Add condition`을 클릭하고 `Path`를 선택합니다.
    *   경로 패턴에 `/error`를 입력합니다. (예: `IF Path is /error`)
    *   필요에 따라 다른 조건을 추가할 수 있습니다. (예: `AND HTTP method is GET`)
5.  **동작(Action) 정의**:
    *   `Add action`을 클릭하고 `Return fixed response`를 선택합니다.
    *   `HTTP response code`를 `404`로 설정합니다.
    *   `Content type`을 `text/plain`으로 설정하고, `Response body`에 `Not found, custom error`와 같은 메시지를 입력합니다.
    *   다른 동작으로는 `Forward to target groups` (다른 타겟 그룹으로 전달) 또는 `Redirect` (다른 URL로 리디렉션) 등이 있습니다.
6.  **우선순위(Priority) 설정**:
    *   규칙의 우선순위를 설정합니다. 숫자가 낮을수록 우선순위가 높습니다. 기본 규칙보다 높은 우선순위를 가지도록 설정해야 합니다. (예: `5`)
7.  **규칙 검토 및 생성**: 설정된 조건을 확인하고 규칙을 생성합니다.

**ALB 리스너 규칙 구성 (개념):**

```
Listener Rule: DemoRule
  Priority: 5
  Conditions:
    - IF Path is /error
  Actions:
    - THEN Return fixed response
      Status Code: 404
      Content Type: text/plain
      Response Body: Not found, custom error

Default Rule:
  Priority: 50000 (default)
  Conditions:
    - IF True (always)
  Actions:
    - THEN Forward to target group (my-demo-target-group)
```

이 규칙이 적용되면, 사용자가 로드 밸런서의 DNS 이름에 `/error` 경로를 붙여 접근(`http://your-alb-dns/error`)하면, 정의된 404 고정 응답 메시지를 받게 됩니다. 반면, `/error`가 아닌 다른 경로로 접근하면 기본 규칙에 따라 백엔드 EC2 인스턴스로 트래픽이 전달됩니다.

이러한 규칙은 특정 API 버전 라우팅, A/B 테스트, 유지보수 페이지 리디렉션 등 다양한 시나리오에 활용될 수 있어 애플리케이션의 유연성과 관리 효율성을 크게 높여줍니다.

## 결론: 로드 밸런서를 통한 안정적이고 유연한 서비스 제공

지금까지 AWS Application Load Balancer를 활용하여 EC2 인스턴스의 네트워크 보안을 강화하고, 고급 리스너 규칙을 통해 트래픽을 유연하게 제어하는 방법을 살펴보았습니다.

EC2 인스턴스 보안 그룹을 로드 밸런서의 보안 그룹과 연동함으로써, 백엔드 인스턴스에 대한 직접적인 외부 접근을 효과적으로 차단하여 보안 취약점을 제거할 수 있습니다. 이는 "최소 권한" 원칙을 준수하며 애플리케이션의 전체적인 보안 태세를 강화하는 데 기여합니다.

또한, ALB 리스너 규칙은 경로 기반, 호스트 기반, HTTP 헤더 기반 등 다양한 조건에 따라 트래픽을 다르게 처리할 수 있는 강력한 기능을 제공합니다. 이를 통해 개발자는 특정 URL 패턴에 대한 커스텀 에러 페이지 제공, 마이크로서비스 간의 트래픽 라우팅, A/B 테스트 구현 등 복잡한 요구사항을 로드 밸런서 수준에서 처리하여 애플리케이션 로직을 단순화하고 성능을 최적화할 수 있습니다.

이러한 고급 로드 밸런서 활용 전략은 클라우드 환경에서 안정적이고 보안성이 높으며 유연한 애플리케이션을 구축하는 데 필수적인 요소입니다. 여러분의 서비스에 이러한 전략을 적용하여 더욱 견고하고 효율적인 인프라를 구축하시기를 바랍니다.
