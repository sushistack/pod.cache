# 060. 🛡️ AWS Gateway Load Balancer: 네트워크 보안 어플라이언스 통합의 새로운 표준

AWS Gateway Load Balancer (GWLB)는 클라우드 환경에서 써드파티 네트워크 보안 및 가시성 어플라이언스를 효율적으로 배포, 확장, 관리할 수 있도록 설계된 로드 밸런서입니다. 모든 네트워크 트래픽을 방화벽, 침입 탐지 시스템(IDS/IPS)과 같은 가상 어플라이언스를 통해 투명하게 라우팅하여 심층 검사 및 처리를 가능하게 합니다. 레이어 3(네트워크 계층)에서 동작하며 GENEVE 프로토콜을 사용하여 기존의 복잡한 네트워크 아키텍처를 단순화합니다.

## 서론: 왜 Gateway Load Balancer가 필요한가?

클라우드 환경으로의 전환이 가속화되면서, 기업들은 온프레미스에서 사용하던 다양한 네트워크 보안 및 모니터링 솔루션들을 클라우드에서도 유사하게 구현하고자 합니다. 하지만 기존의 로드 밸런서나 네트워크 구성으로는 이러한 써드파티 가상 어플라이언스들을 효과적으로 통합하고 관리하는 데 여러 어려움이 있었습니다.

### 기존 네트워크 보안 어플라이언스 통합의 어려움

과거에는 애플리케이션으로 향하는 모든 트래픽을 방화벽, 침입 탐지/방지 시스템(IDS/IPS), 딥 패킷 인스펙션(DPI) 시스템과 같은 써드파티 가상 어플라이언스를 거치도록 구성하는 것이 매우 복잡했습니다. 수동으로 라우팅 테이블을 조작하거나, 여러 네트워크 인터페이스를 관리하고, 어플라이언스의 가용성을 확보하기 위한 추가적인 노력이 필요했습니다. 이는 곧 복잡한 아키텍처, 높은 운영 비용, 그리고 확장성의 한계로 이어졌습니다.

### GWLB의 등장 배경과 목적

AWS Gateway Load Balancer는 이러한 문제점들을 해결하기 위해 등장했습니다. GWLB의 주된 목적은 AWS 클라우드 환경에서 써드파티 네트워크 가상 어플라이언스(예: EC2 인스턴스에 배포된 방화벽 소프트웨어)를 배포, 확장, 관리하는 과정을 단순화하고 자동화하는 것입니다. 이를 통해 개발자와 운영팀은 네트워크 보안 및 가시성 요구사항을 충족하면서도, 핵심 애플리케이션 개발에 더욱 집중할 수 있게 되었습니다.

## Gateway Load Balancer란 무엇인가?

Gateway Load Balancer는 네트워크 트래픽을 가상 어플라이언스 플릿으로 전달하고, 어플라이언스가 트래픽을 처리한 후 다시 애플리케이션으로 보내는 과정을 총괄합니다. 이는 마치 모든 네트워크 트래픽이 어플라이언스를 거쳐가야 하는 "투명한 게이트웨이" 역할을 수행합니다.

### 핵심 기능 및 주요 활용 사례

GWLB는 다음과 같은 시나리오에서 특히 유용하게 활용됩니다.

*   **방화벽(Firewall):** 모든 인바운드 및 아웃바운드 트래픽을 중앙 집중식 방화벽을 통해 필터링하여 보안 정책을 적용합니다.
*   **침입 탐지 및 방지 시스템 (IDS/IPS):** 네트워크 트래픽에서 악성 활동이나 비정상적인 패턴을 탐지하고 차단합니다.
*   **심층 패킷 검사 (Deep Packet Inspection, DPI):** 애플리케이션 계층까지 트래픽 내용을 분석하여 특정 콘텐츠나 위협을 식별합니다.
*   **네트워크 레벨 페이로드 수정:** 특정 조건에 따라 네트워크 트래픽의 페이로드를 수정해야 하는 경우에 사용됩니다.

### GWLB의 동작 원리: 트래픽 흐름 해부

GWLB의 동작은 VPC 라우팅 테이블 업데이트를 통해 이루어집니다. 사용자의 트래픽이 애플리케이션에 도달하기 전에 Gateway Load Balancer를 반드시 거치도록 설정되는 것이 핵심입니다.

다음은 GWLB를 통한 트래픽 흐름의 단계별 설명입니다.

1.  **사용자 트래픽 발생:** 외부 사용자가 애플리케이션에 접근을 시도합니다.
2.  **VPC 라우팅 업데이트:** VPC 라우팅 테이블은 모든 인바운드 트래픽이 애플리케이션으로 직접 가는 대신, 먼저 Gateway Load Balancer를 통과하도록 설정됩니다.
3.  **GWLB로 트래픽 전송:** 사용자 트래픽은 Gateway Load Balancer로 전달됩니다.
4.  **어플라이언스 플릿으로 분산:** GWLB는 수신된 트래픽을 미리 정의된 타겟 그룹(예: 방화벽 역할을 하는 EC2 인스턴스 플릿)의 가상 어플라이언스 중 하나로 분산시킵니다.
5.  **트래픽 검사 및 처리:** 가상 어플라이언스는 트래픽을 수신하여 보안 정책에 따라 검사하고 처리합니다. (예: 악성 트래픽 차단, 로깅, 페이로드 수정 등)
6.  **GWLB로 트래픽 반환:** 어플라이언스가 트래픽을 처리한 후, 유효한 트래픽은 다시 Gateway Load Balancer로 반환됩니다. (유효하지 않은 트래픽은 어플라이언스에서 드롭될 수 있습니다.)
7.  **애플리케이션으로 최종 전달:** GWLB는 어플라이언스로부터 반환된 트래픽을 최종 목적지인 애플리케이션으로 전달합니다.
8.  **애플리케이션 투명성:** 이 모든 과정은 애플리케이션 입장에서는 완전히 투명하게 이루어집니다. 애플리케이션은 마치 GWLB가 없는 것처럼 직접 트래픽을 수신하는 것으로 인지합니다.

이러한 메커니즘을 통해, GWLB는 네트워크 트래픽을 어플라이언스 플릿으로 보내고 받는 **단일 진입점 및 종료점(Single Entry & Exit Point)** 역할을 수행합니다.

## Gateway Load Balancer의 주요 특징

GWLB는 기존 로드 밸런서와 차별화되는 몇 가지 중요한 특징을 가지고 있습니다.

### 레이어 3 동작과 GENEVE 프로토콜

GWLB는 OSI 모델의 **레이어 3 (네트워크 계층)**에서 작동합니다. 이는 IP 패킷 수준에서 트래픽을 처리한다는 의미입니다. 다른 AWS 로드 밸런서(예: Application Load Balancer는 L7, Network Load Balancer는 L4)와 달리, GWLB는 저수준의 네트워크 트래픽을 다룹니다.

또한, GWLB는 가상 어플라이언스와의 통신을 위해 **GENEVE (Generic Network Virtualization Encapsulation) 프로토콜**을 사용합니다. GENEVE는 UDP 포트 **6081**을 사용하며, 원본 IP 패킷을 캡슐화하여 어플라이언스로 전달합니다. 어플라이언스는 이 캡슐화된 패킷을 디캡슐화하여 처리한 후, 다시 GENEVE로 캡슐화하여 GWLB로 반환합니다. 이 과정을 통해 원본 트래픽의 IP 헤더 정보가 보존되며, 어플라이언스가 네트워크 스택 변경 없이 트래픽을 처리할 수 있습니다.

### 유연한 타겟 그룹 구성

GWLB의 타겟 그룹은 네트워크 가상 어플라이언스로 구성됩니다. 다음 두 가지 방식으로 어플라이언스를 타겟으로 등록할 수 있습니다.

| 타겟 유형           | 설명                                                                                                                              | 활용 사례                                                 |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------- |
| **EC2 인스턴스**    | AWS 내에서 실행되는 EC2 인스턴스를 인스턴스 ID로 등록합니다. 이 인스턴스에 써드파티 방화벽, IDS/IPS 등의 소프트웨어를 배포합니다. | AWS 클라우드 내에서 네트워크 보안 어플라이언스를 운영할 때 |
| **프라이빗 IP 주소** | VPC 내의 프라이빗 IP 주소 또는 AWS Direct Connect/VPN을 통해 연결된 온프레미스 데이터 센터의 어플라이언스 IP를 등록합니다.         | 하이브리드 클라우드 환경에서 온프레미스 어플라이언스 연동 |

이러한 유연한 타겟 그룹 구성을 통해, 기업은 온프레미스에 구축된 기존 보안 솔루션들을 AWS 환경과 통합하거나, 클라우드 네이티브 방식으로 보안 어플라이언스를 확장할 수 있습니다.

## 결론: 차세대 네트워크 보안을 위한 필수 요소

AWS Gateway Load Balancer는 클라우드 환경에서 복잡한 네트워크 보안 및 가시성 요구사항을 충족시키는 데 있어 혁신적인 솔루션입니다. 써드파티 가상 어플라이언스들을 투명하고 확장 가능하며 고가용성으로 통합함으로써, 기존의 복잡한 아키텍처 문제를 해결하고 운영의 편의성을 극대화합니다.

GWLB의 등장은 네트워크 아키텍처 설계의 패러다임을 변화시키며, 개발자와 인프라 엔지니어가 보안과 성능이라는 두 마리 토끼를 모두 잡을 수 있도록 돕습니다. 앞으로 AWS 클라우드에서 심층적인 네트워크 트래픽 검사와 보안 정책 적용이 필요한 경우, Gateway Load Balancer는 반드시 고려해야 할 핵심 서비스가 될 것입니다.
