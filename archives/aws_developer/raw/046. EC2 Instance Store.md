# 046. 🚀 EC2 인스턴스 스토어: 초고속 성능, 임시 데이터의 최강자

## 3줄 요약

*   EC2 인스턴스 스토어는 EC2 인스턴스가 실행되는 물리 서버에 직접 연결된 하드웨어 디스크로, 네트워크 드라이브(EBS)보다 훨씬 높은 I/O 성능을 제공합니다.
*   버퍼, 캐시, 스크래치 데이터 또는 임시 콘텐츠 등 극도로 빠른 디스크 I/O가 필요한 애플리케이션에 최적화되어 있습니다.
*   하지만 인스턴스 중지 또는 종료 시 데이터가 영구히 소실되는 휘발성 스토리지이므로, 장기적인 데이터 보관용으로는 부적합하며 데이터 백업 및 복제는 사용자의 책임입니다.

---

## 서론: 고성능 스토리지의 필요성

클라우드 환경에서 EC2 인스턴스는 다양한 애플리케이션의 핵심 기반이 됩니다. 우리는 흔히 EC2 인스턴스에 네트워크 기반의 영구 스토리지인 EBS(Elastic Block Store)를 연결하여 사용합니다. EBS는 유연하고 내구성이 뛰어나며 데이터 보존성이 보장되지만, 때로는 특정 워크로드에서 요구하는 압도적인 수준의 I/O 성능을 충족시키기 어려울 수 있습니다. 데이터베이스의 캐싱 계층, 실시간 분석을 위한 버퍼, 대규모 병렬 처리의 중간 데이터 저장 등 극도로 낮은 지연 시간과 높은 처리량이 필요한 시나리오에서는 기존 네트워크 드라이브의 한계를 뛰어넘는 솔루션이 필요합니다. 이때 AWS EC2 인스턴스 스토어가 강력한 대안으로 떠오릅니다.

## 본론: EC2 인스턴스 스토어의 이해와 활용

### EC2 인스턴스 스토어란?

EC2 인스턴스 스토어는 EC2 인스턴스가 실행되는 **물리적 호스트 서버에 직접 연결된 하드웨어 디스크**를 의미합니다. EC2 인스턴스는 가상 머신이지만, 실제 물리 서버 위에서 구동되며, 이 물리 서버에 내장된 디스크 공간을 활용하는 것이 바로 인스턴스 스토어입니다. 이는 네트워크를 통해 접근하는 EBS와 달리, 물리적 연결을 통해 데이터를 읽고 쓰기 때문에 훨씬 더 빠른 I/O 성능을 기대할 수 있습니다.

### 압도적인 성능의 비결

인스턴스 스토어의 가장 큰 장점은 바로 그 **압도적인 성능**에 있습니다. 네트워크 오버헤드 없이 물리적으로 직접 연결되어 있어, 매우 높은 IOPS(Input/Output Operations Per Second)와 처리량을 자랑합니다.

예를 들어, 고성능 컴퓨팅(HPC) 워크로드에 자주 사용되는 `I3` 인스턴스 계열을 살펴보겠습니다. 이 인스턴스들은 인스턴스 스토어를 내장하고 있으며, 그 성능은 다음과 같습니다.

| 스토리지 유형                | 랜덤 읽기 IOPS | 랜덤 쓰기 IOPS |
| :--------------------------- | :------------- | :------------- |
| **EC2 인스턴스 스토어 (NVMe SSD)** | 최대 330만 IOPS | 최대 140만 IOPS |
| EBS GP2 (비교군)             | 최대 3만 2천 IOPS | 최대 3만 2천 IOPS |

이 수치에서 볼 수 있듯이, EC2 인스턴스 스토어는 EBS GP2 볼륨과 비교했을 때 수십 배에서 수백 배에 달하는 I/O 성능을 제공합니다. 이는 대규모 데이터셋 처리, 고성능 데이터베이스, 캐싱 서버 등 높은 디스크 성능이 필수적인 환경에서 빛을 발합니다.

### 휘발성 스토리지의 명과 암

EC2 인스턴스 스토어는 탁월한 성능을 제공하지만, 중요한 제약 사항이 있습니다. 바로 **휘발성(Ephemeral) 스토리지**라는 점입니다.

```
Warning: Instance Store data is ephemeral!
```

이는 EC2 인스턴스가 `중지(Stop)`되거나 `종료(Terminate)`될 경우, 해당 인스턴스 스토어에 저장된 모든 데이터가 영구적으로 소실된다는 것을 의미합니다. 또한, 인스턴스가 실행 중인 물리 서버 자체에 장애가 발생하더라도 데이터 손실의 위험이 있습니다. 이 때문에 인스턴스 스토어는 장기적인 데이터 보관이나 영구적인 스토리지로는 적합하지 않습니다.

**✅ EC2 인스턴스 스토어의 적절한 사용 사례:**

*   **캐시(Cache) 서버:** 데이터베이스 또는 애플리케이션의 캐싱 계층으로 활용하여 응답 시간을 단축합니다.
*   **버퍼(Buffer):** 스트리밍 데이터 처리, 로그 수집 등 일시적으로 데이터를 저장하고 처리해야 하는 경우에 사용합니다.
*   **스크래치 데이터(Scratch Data):** 대규모 분석 작업의 중간 결과물 또는 임시 파일을 빠르게 읽고 써야 할 때 유용합니다.
*   **임시 콘텐츠(Temporary Content):** 미디어 인코딩, 이미지 처리 등 작업 완료 후 필요 없는 임시 데이터를 저장합니다.
*   **복제 가능한 데이터 저장:** 데이터가 다른 곳에 복제되어 있어 손실되어도 복구가 가능한 시나리오.

**❌ EC2 인스턴스 스토어를 피해야 할 사용 사례:**

*   영구적으로 보존해야 할 데이터베이스의 주 스토리지
*   운영체제 루트 볼륨 (일반적으로 EBS 사용)
*   중요한 애플리케이션 구성 파일
*   단일 장애 지점이 될 수 있는 모든 데이터

인스턴스 스토어 사용 시 데이터 손실에 대한 책임은 전적으로 사용자에게 있습니다. 따라서 만약 인스턴스 스토어에 저장된 데이터의 보존이 필요하다면, 반드시 애플리케이션 계층에서 주기적인 백업 또는 다른 영구 스토리지로의 복제 메커니즘을 구현해야 합니다.

## 결론: 성능과 내구성 사이의 현명한 선택

EC2 인스턴스 스토어는 AWS 클라우드에서 제공하는 가장 빠른 블록 스토리지 옵션 중 하나입니다. 극도로 높은 I/O 성능이 요구되는 특정 워크로드에 최적화되어 있으며, 캐시, 버퍼, 스크래치 공간 등 임시 데이터 처리에서 독보적인 효율성을 제공합니다.

그러나 그 휘발성 특성 때문에 데이터의 영구성이 중요한 경우에는 적합하지 않습니다. 개발자는 애플리케이션의 요구 사항을 정확히 이해하고, 성능과 데이터 내구성 사이의 트레이드오프를 고려하여 EC2 인스턴스 스토어와 EBS와 같은 영구 스토리지 옵션을 현명하게 선택하고 조합해야 합니다. 초고속의 성능이 필요한가요? 그렇다면 EC2 인스턴스 스토어를 고려해볼 때입니다. 다만, 데이터 손실 위험을 감수할 준비가 되어 있는지, 혹은 그에 대한 대비책을 마련할 수 있는지 반드시 확인해야 할 것입니다.
