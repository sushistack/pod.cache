# 055. 🌐 AWS Application Load Balancer로 지능형 트래픽 관리하기

AWS Application Load Balancer(ALB)는 HTTP/HTTPS 트래픽 분산에 특화된 레이어 7 로드 밸런서입니다. URL 경로, 호스트명, 쿼리 스트링 등 다양한 조건으로 요청을 여러 타겟 그룹으로 지능적으로 라우팅합니다. 마이크로서비스 및 컨테이너 기반 애플리케이션 환경에 최적화되어 탁월한 확장성과 유연성을 제공합니다.

---

## 서론: 현대 웹 서비스의 필수 요소, 로드 밸런싱

오늘날의 웹 애플리케이션은 사용자에게 끊김 없는 서비스를 제공하기 위해 높은 가용성과 확장성을 요구합니다. 이러한 요구사항을 충족시키기 위한 핵심 기술 중 하나가 바로 로드 밸런서입니다. 특히, AWS Application Load Balancer (ALB)는 HTTP 및 HTTPS 트래픽을 효율적으로 관리하고 분산하여 마이크로서비스 아키텍처와 컨테이너 기반 환경에서 강력한 성능을 발휘합니다. 이번 아티클에서는 ALB의 주요 특징과 고급 라우팅 기능, 그리고 마이크로서비스 환경에서의 활용 방안을 심층적으로 다루어 보겠습니다.

## 본론: Application Load Balancer의 심층 탐구

### ALB의 핵심 특징과 장점

Application Load Balancer (ALB)는 OSI 7계층 중 애플리케이션 계층(Layer 7)에서 동작하는 로드 밸런서입니다. 이는 ALB가 단순히 네트워크 트래픽을 분산하는 것을 넘어, HTTP 및 HTTPS 프로토콜의 특성을 이해하고 요청 내용을 기반으로 트래픽을 조작하고 라우팅할 수 있음을 의미합니다.

*   **레이어 7 전용:** HTTP, HTTPS 트래픽에 최적화되어 있으며, 요청의 내용을 분석하여 라우팅 결정을 내립니다.
*   **다중 애플리케이션 지원:** 하나의 ALB 뒤에 여러 개의 HTTP 애플리케이션을 배치하고 관리할 수 있습니다. 이는 기존 Classic Load Balancer가 애플리케이션당 하나의 로드 밸런서가 필요했던 것과 대조적입니다.
*   **프로토콜 지원:** HTTP/2 및 WebSockets를 지원하여 최신 웹 기술을 활용하는 애플리케이션에 적합합니다.
*   **자동 리디렉션:** HTTP 요청을 자동으로 HTTPS로 리디렉션하는 기능을 제공하여 보안을 강화하고 관리 부담을 줄여줍니다.

### 고급 라우팅 기능: 트래픽을 더욱 세밀하게 제어하다

ALB의 가장 강력한 기능 중 하나는 유연하고 강력한 라우팅 규칙입니다. 이는 특정 요청을 특정 타겟 그룹으로 전달하여 마이크로서비스 아키텍처를 구현하고, A/B 테스트, 카나리 배포 등 다양한 배포 전략을 지원하는 데 필수적입니다.

#### 1. URL 경로 기반 라우팅 (Path-based Routing)

URL의 경로(Path)에 따라 요청을 다른 타겟 그룹으로 라우팅할 수 있습니다. 예를 들어, `/users`로 시작하는 요청은 사용자 관리 서비스로, `/posts`로 시작하는 요청은 게시글 관리 서비스로 보낼 수 있습니다.

```
Request: example.com/users/*  -> Target Group: User Service EC2 Instances
Request: example.com/posts/*  -> Target Group: Post Service EC2 Instances
```

#### 2. 호스트명 기반 라우팅 (Host-based Routing)

URL의 호스트명(Host name)에 따라 요청을 다른 타겟 그룹으로 라우팅할 수 있습니다. 이는 동일한 ALB를 사용하여 여러 도메인 또는 서브도메인의 트래픽을 처리할 때 유용합니다.

```
Request: one.example.com/*   -> Target Group: Application A EC2 Instances
Request: other.example.com/* -> Target Group: Application B EC2 Instances
```

#### 3. 쿼리 스트링 및 HTTP 헤더 기반 라우팅 (Query String & Header-based Routing)

요청 URL의 쿼리 스트링(Query String)이나 HTTP 헤더(Header)의 내용을 기반으로 라우팅 규칙을 설정할 수 있습니다. 이는 모바일/데스크톱 사용자 구분, 특정 사용자 그룹 대상 기능 제공 등에 활용될 수 있습니다.

**예시: 쿼리 스트링 기반 라우팅**

| 조건                 | 라우팅 대상 타겟 그룹                  |
| :------------------- | :------------------------------------- |
| `?platform=mobile`   | 모바일 앱용 백엔드 타겟 그룹 (예: EC2) |
| `?platform=desktop`  | 데스크톱 앱용 백엔드 타겟 그룹 (예: 온프레미스 서버) |

### 타겟 그룹(Target Group)의 이해

ALB는 요청을 처리할 대상 서버들을 `타겟 그룹`이라는 논리적인 그룹으로 묶습니다. 각 타겟 그룹은 독립적인 헬스 체크를 수행하며, ALB는 헬스 체크를 통과한 타겟에게만 트래픽을 전달합니다.

ALB가 지원하는 타겟 유형은 다음과 같습니다.

*   **EC2 인스턴스:** 가장 일반적인 형태로, Auto Scaling Group과 연동하여 자동으로 확장/축소될 수 있습니다.
*   **ECS(Elastic Container Service) 태스크:** 컨테이너 기반 애플리케이션을 위한 핵심 타겟 유형입니다.
*   **Lambda 함수:** 서버리스 아키텍처를 구현할 때 ALB를 프런트엔드로 사용할 수 있습니다.
*   **IP 주소:** AWS 클라우드 외부의 온프레미스 서버나 다른 VPC의 리소스 등 특정 IP 주소로도 트래픽을 라우팅할 수 있습니다 (단, 사설 IP 주소여야 함).

### 마이크로서비스 및 컨테이너 환경에서의 ALB

ALB는 마이크로서비스와 컨테이너 기반 애플리케이션(특히 Docker 및 Amazon ECS)에 최적화된 로드 밸런서입니다.

**동적 포트 매핑:** ECS 환경에서 컨테이너는 호스트 EC2 인스턴스의 동적 포트에 할당될 수 있습니다. ALB는 이러한 동적 포트 매핑 기능을 지원하여, 컨테이너가 어떤 포트에서 실행되든지 관계없이 트래픽을 올바르게 라우팅할 수 있습니다. 이는 컨테이너 기반 서비스의 유연성과 확장성을 극대화하는 데 크게 기여합니다.

### ALB 사용 시 고려사항

ALB를 사용할 때 개발자가 알아야 할 몇 가지 중요한 사항이 있습니다.

#### 1. 고정 호스트명

ALB는 생성 시 고유한 고정 호스트명(예: `my-alb-123456789.us-east-1.elb.amazonaws.com`)을 제공합니다. 애플리케이션은 이 호스트명을 통해 ALB에 접근하며, 일반적으로 Route 53과 같은 DNS 서비스를 사용하여 사용자 친화적인 도메인(예: `app.example.com`)으로 매핑하여 사용합니다.

#### 2. 클라이언트 IP 주소 전달 (X-Forwarded-* 헤더)

ALB는 클라이언트의 요청을 받아 타겟 그룹의 인스턴스로 전달할 때, 클라이언트와 직접 통신하는 대신 ALB 자체가 중간에서 연결을 종료하고 새로운 연결을 타겟 인스턴스와 수립합니다. 이 때문에 백엔드 애플리케이션 서버는 클라이언트의 실제 IP 주소를 직접 볼 수 없습니다.

대신 ALB는 클라이언트의 실제 정보를 다음 HTTP 헤더에 추가하여 백엔드 서버로 전달합니다.

*   `X-Forwarded-For`: 클라이언트의 실제 IP 주소.
*   `X-Forwarded-Port`: 클라이언트가 사용한 포트.
*   `X-Forwarded-Proto`: 클라이언트가 사용한 프로토콜 (HTTP 또는 HTTPS).

따라서 백엔드 애플리케이션은 클라이언트의 실제 IP 주소나 프로토콜 정보를 얻기 위해 이 헤더들을 파싱해야 합니다.

**통신 흐름 예시:**

1.  **클라이언트 (12.34.56.78) -> ALB:** 클라이언트 IP는 `12.34.56.78`.
2.  **ALB (ALB의 Private IP) -> EC2 인스턴스:** EC2 인스턴스는 ALB의 Private IP를 발신지로 인식.
3.  **EC2 인스턴스에서 클라이언트 IP 확인:**
    *   요청 헤더에서 `X-Forwarded-For: 12.34.56.78` 확인.
    *   요청 헤더에서 `X-Forwarded-Port: [클라이언트 포트]` 확인.
    *   요청 헤더에서 `X-Forwarded-Proto: [http 또는 https]` 확인.

```python
# Python Flask 예시 (클라이언트 IP 추출)
from flask import Flask, request

app = Flask(__name__)

@app.route('/')
def hello():
    client_ip = request.headers.get('X-Forwarded-For', request.remote_addr)
    client_port = request.headers.get('X-Forwarded-Port')
    client_proto = request.headers.get('X-Forwarded-Proto')
    return f"Hello from Flask! Your IP: {client_ip}, Port: {client_port}, Protocol: {client_proto}"

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=80)
```

위 Python Flask 예시처럼 애플리케이션 로직에서 `X-Forwarded-For` 헤더를 참조하여 클라이언트 IP를 얻어야 합니다.

## 결론: 현대 아키텍처의 필수 인프라, ALB

AWS Application Load Balancer는 현대 웹 애플리케이션, 특히 마이크로서비스 및 컨테이너 기반 아키텍처에 필수적인 인프라 구성 요소입니다. 레이어 7에서의 지능적인 트래픽 라우팅 기능은 복잡한 서비스 환경에서도 유연하고 효율적인 트래픽 관리를 가능하게 합니다. 또한, 다양한 타겟 유형 지원과 `X-Forwarded-*` 헤더를 통한 클라이언트 정보 전달 방식은 개발자가 ALB의 작동 방식을 정확히 이해하고 애플리케이션을 설계할 때 중요한 가이드라인을 제공합니다.

ALB의 강력한 기능을 숙지하고 활용한다면, 고가용성, 확장성, 그리고 높은 성능을 갖춘 안정적인 애플리케이션을 구축하는 데 큰 도움이 될 것입니다. 이제 실습을 통해 직접 ALB를 구성하고 그 위력을 경험해볼 시간입니다!
