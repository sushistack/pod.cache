# 031. 🛡️ AWS EC2 보안 그룹 마스터하기: 네트워크 방화벽 심층 분석

AWS EC2 인스턴스의 네트워크 보안은 클라우드 환경에서 애플리케이션을 안전하게 운영하는 데 필수적입니다. 이 아티클에서는 EC2 인스턴스의 트래픽을 제어하는 핵심 도구인 보안 그룹(Security Group)에 대해 심층적으로 다룹니다. 보안 그룹의 기본 원리부터 고급 활용법, 그리고 반드시 알아야 할 주요 포트까지, 개발자가 알아두면 유익할 정보를 제공합니다.

---

### 3줄 요약

*   AWS 보안 그룹은 EC2 인스턴스 앞단의 가상 방화벽으로, 인바운드 및 아웃바운드 네트워크 트래픽을 제어합니다.
*   오직 '허용(Allow)' 규칙만으로 동작하며, IP 주소 범위 또는 다른 보안 그룹을 통해 트래픽 소스를 지정할 수 있습니다.
*   기본적으로 모든 인바운드 트래픽은 차단되고 모든 아웃바운드 트래픽은 허용되므로, 적절한 규칙 설정을 통해 보안을 강화해야 합니다.

---

## 1. 서론: EC2 보안의 첫 번째 관문, 보안 그룹

클라우드 시대의 애플리케이션은 네트워크를 통해 다양한 서비스와 상호작용합니다. 이때 가장 중요한 것은 외부로부터의 위협으로부터 시스템을 보호하고, 허용된 트래픽만 오갈 수 있도록 관리하는 것입니다. AWS EC2 인스턴스에 있어서 이러한 역할을 담당하는 핵심 요소가 바로 **보안 그룹(Security Group)**입니다.

보안 그룹은 EC2 인스턴스에 대한 가상 방화벽 역할을 수행하며, 인스턴스에 들어오고 나가는 네트워크 트래픽을 효과적으로 제어합니다. 단순히 포트를 열고 닫는 것을 넘어, 트래픽의 소스와 목적지까지 세밀하게 정의할 수 있어 강력한 보안 정책을 구현할 수 있도록 돕습니다.

## 2. 본론: 보안 그룹의 작동 방식과 활용

### 2.1. 보안 그룹이란 무엇인가?

AWS 보안 그룹은 EC2 인스턴스 수준에서 작동하는 상태 저장(stateful) 방화벽입니다. 이는 한번 허용된 인바운드 트래픽에 대한 응답 트래픽은 별도의 아웃바운드 규칙 없이도 자동으로 허용됨을 의미합니다.

핵심 특징은 다음과 같습니다:
*   **허용 규칙만 포함**: 보안 그룹은 오직 허용(allow) 규칙만 포함합니다. 즉, 명시적으로 허용되지 않은 모든 트래픽은 암묵적으로 차단됩니다.
*   **인바운드 및 아웃바운드 제어**: 인스턴스로 들어오는(Inbound) 트래픽과 인스턴스에서 나가는(Outbound) 트래픽 모두를 제어합니다.
*   **트래픽 소스 지정**: 트래픽의 소스를 특정 IP 주소 범위(IPv4 또는 IPv6)로 지정하거나, 다른 보안 그룹을 참조하여 지정할 수 있습니다.

### 2.2. 보안 그룹 규칙의 구성 요소

보안 그룹 규칙은 다음과 같은 요소들로 구성됩니다.

*   **유형 (Type)**: 트래픽의 종류를 나타냅니다. (예: SSH, HTTP, HTTPS, 사용자 지정 TCP 등)
*   **프로토콜 (Protocol)**: 사용할 네트워크 프로토콜을 지정합니다. (예: TCP, UDP, ICMP 등)
*   **포트 범위 (Port Range)**: 트래픽이 허용될 포트 번호 또는 포트 범위입니다. (예: 22, 80, 443 등)
*   **소스/대상 (Source/Destination)**:
    *   **인바운드 규칙**: 트래픽이 허용될 IP 주소 범위(CIDR 블록) 또는 다른 보안 그룹을 지정합니다.
    *   **아웃바운드 규칙**: 트래픽이 나갈 IP 주소 범위(CIDR 블록) 또는 다른 보안 그룹을 지정합니다.

**예시: 웹 서버 보안 그룹 규칙**

| 유형    | 프로토콜 | 포트 범위 | 소스             | 설명        |
| :------ | :------- | :-------- | :--------------- | :---------- |
| SSH     | TCP      | 22        | 내 IP 주소/32    | SSH 접속    |
| HTTP    | TCP      | 80        | 0.0.0.0/0        | 웹 서버 접근 |
| HTTPS   | TCP      | 443       | 0.0.0.0/0        | 보안 웹 서버 |

위 표에서 `0.0.0.0/0`은 모든 IP 주소를 의미하며, 웹 서버와 같이 공용으로 접근되어야 하는 서비스에 주로 사용됩니다. 특정 IP 주소만을 허용하려면 `XX.XX.XX.XX/32`와 같이 지정할 수 있습니다.

### 2.3. 보안 그룹의 주요 특성 및 고려 사항

보안 그룹을 효과적으로 사용하기 위한 추가적인 특성들을 이해하는 것이 중요합니다.

*   **다대다 관계**: 하나의 보안 그룹은 여러 EC2 인스턴스에 연결될 수 있으며, 하나의 EC2 인스턴스 또한 여러 보안 그룹에 연결될 수 있습니다.
*   **지역(Region) 및 VPC(Virtual Private Cloud) 종속성**: 보안 그룹은 특정 AWS 지역(Region) 및 VPC에 종속됩니다. 다른 지역이나 VPC에서 사용하려면 새로 생성해야 합니다.
*   **EC2 인스턴스 외부에서 작동**: 보안 그룹은 EC2 인스턴스 자체보다 한 단계 앞단에서 작동하는 방화벽입니다. 따라서 트래픽이 보안 그룹에 의해 차단되면, EC2 인스턴스는 해당 트래픽의 존재조차 인지하지 못합니다.
*   **기본 설정**:
    *   모든 **인바운드 트래픽**은 기본적으로 **차단**됩니다.
    *   모든 **아웃바운드 트래픽**은 기본적으로 **허용**됩니다.
*   **문제 해결 팁**:
    *   **"연결 시간 초과(Connection Timeout)"** 오류 발생 시: 보안 그룹 문제일 가능성이 높습니다. 인바운드 규칙이 올바르게 설정되었는지 확인하세요.
    *   **"연결 거부됨(Connection Refused)"** 오류 발생 시: 보안 그룹은 트래픽을 허용했지만, 인스턴스 내의 애플리케이션(서비스)이 실행되고 있지 않거나, 잘못 구성되었을 가능성이 높습니다.

### 2.4. 고급 활용: 보안 그룹 상호 참조

보안 그룹의 강력한 기능 중 하나는 다른 보안 그룹을 소스 또는 대상으로 지정할 수 있다는 점입니다. 이는 마이크로서비스 아키텍처나 다중 계층 애플리케이션에서 매우 유용합니다.

**예시 시나리오:**
웹 서버(EC2-A)와 데이터베이스 서버(EC2-B)가 있다고 가정해 봅시다. 웹 서버는 데이터베이스 서버에 접근해야 하지만, 외부에서는 데이터베이스 서버에 직접 접근할 수 없어야 합니다.

1.  **웹 서버 보안 그룹 (SG-Web)**:
    *   인바운드 규칙: HTTP(80), HTTPS(443) 트래픽을 `0.0.0.0/0`에서 허용.
    *   아웃바운드 규칙: 기본 허용.

2.  **데이터베이스 서버 보안 그룹 (SG-DB)**:
    *   인바운드 규칙: `SG-Web`으로부터의 MySQL(3306) 트래픽만 허용.
    *   아웃바운드 규칙: 기본 허용.

이렇게 설정하면, `SG-Web`이 연결된 모든 EC2 인스턴스는 `SG-DB`가 연결된 EC2 인스턴스의 특정 포트에 접근할 수 있게 됩니다. EC2 인스턴스의 IP 주소가 변경되더라도 보안 그룹 참조를 통해 자동으로 반영되므로, IP 주소 관리에 대한 부담을 줄일 수 있습니다. 이는 로드 밸런서와 백엔드 인스턴스 간의 통신을 설정할 때도 매우 유용하게 활용됩니다.

### 2.5. 개발자가 알아야 할 주요 포트 번호

클라우드 환경에서 작업할 때 일반적으로 사용되는 몇 가지 필수 포트 번호가 있습니다.

| 포트 번호 | 프로토콜 | 설명                                                                                   | 사용 예시                                   |
| :-------- | :------- | :------- | :-------------------------------------------------------------------------- |
| 22        | TCP      | SSH (Secure Shell)                                                                     | Linux EC2 인스턴스에 원격 접속, SFTP (Secure File Transfer Protocol) |
| 21        | TCP      | FTP (File Transfer Protocol)                                                           | 파일 서버에 파일 업로드/다운로드 (보안에 취약)      |
| 80        | TCP      | HTTP (Hypertext Transfer Protocol)                                                     | 암호화되지 않은 웹 사이트 접속                   |
| 443       | TCP      | HTTPS (Hypertext Transfer Protocol Secure)                                             | 암호화된 웹 사이트 접속 (오늘날의 표준)             |
| 3389      | TCP      | RDP (Remote Desktop Protocol)                                                          | Windows EC2 인스턴스에 원격 데스크톱 접속         |

이러한 포트들은 AWS 자격증 시험에서도 자주 출제되므로, 그 용도를 정확히 이해하고 있는 것이 중요합니다.

## 3. 결론: EC2 보안 그룹, 안전한 클라우드 환경의 초석

AWS EC2 보안 그룹은 클라우드 인프라의 네트워크 보안을 위한 가장 기본적이면서도 강력한 도구입니다. 인바운드 및 아웃바운드 트래픽을 세밀하게 제어함으로써, EC2 인스턴스를 외부 위협으로부터 보호하고, 애플리케이션의 안정적인 운영을 보장할 수 있습니다.

보안 그룹의 작동 원리를 정확히 이해하고, 최소 권한 원칙(Principle of Least Privilege)에 따라 필요한 포트와 소스만 허용하는 규칙을 설정하는 것이 중요합니다. 또한, 보안 그룹 간의 참조 기능을 활용하여 복잡한 아키텍처의 네트워크 보안을 효율적으로 관리할 수 있습니다.

EC2 인스턴스를 다룬다면, 보안 그룹에 대한 숙지는 필수입니다. 이 지식을 바탕으로 더욱 견고하고 안전한 클라우드 솔루션을 구축하시길 바랍니다.
