# 047. ✨ AWS EBS 볼륨, 어떤 타입을 골라야 할까? 개발자를 위한 완벽 가이드

AWS Elastic Block Store (EBS)는 Amazon EC2 인스턴스에서 사용할 수 있는 영구 블록 스토리지 서비스입니다. 올바른 EBS 볼륨 타입을 선택하는 것은 애플리케이션의 성능, 비용 효율성 및 안정성을 결정하는 핵심 요소입니다. 이 글에서는 AWS에서 제공하는 다양한 EBS 볼륨 타입을 살펴보고, 각 타입의 특징과 적합한 워크로드를 분석하여 여러분의 프로젝트에 최적의 선택을 할 수 있도록 돕겠습니다.

---

## AWS EBS 볼륨-타입 톺아보기

AWS EBS는 크게 SSD 기반과 HDD 기반의 두 가지 카테고리로 나뉘며, 현재 총 6가지 볼륨 타입을 제공합니다. 각 타입은 IOPS (초당 입출력 작업 수), 처리량(Throughput), 비용 및 용도에 따라 고유한 특성을 가집니다.

### 1. 범용 SSD (General Purpose SSD): gp2 & gp3

범용 SSD 볼륨은 광범위한 워크로드에서 가격과 성능의 균형을 제공하는 다목적 스토리지입니다. EC2 인스턴스의 부트 볼륨으로 사용될 수 있으며, 개발/테스트 환경이나 가상 데스크톱에 적합합니다.

#### gp2: 구세대 범용 SSD

*   **특징**: 볼륨 크기에 따라 IOPS가 자동으로 프로비저닝됩니다 (1GB당 3 IOPS). 작은 볼륨은 최대 3,000 IOPS까지 버스트 성능을 제공합니다. 최대 IOPS는 16,000 IOPS입니다.
*   **용량**: 1GB ~ 16TB
*   **단점**: IOPS와 볼륨 크기가 연동되어 있어, 더 높은 IOPS가 필요하면 불필요하게 볼륨 크기를 늘려야 할 수 있습니다.

#### gp3: 신세대 범용 SSD

*   **특징**: gp2의 차세대 볼륨으로, IOPS와 처리량을 볼륨 크기와 관계없이 독립적으로 설정할 수 있어 유연성이 높고 비용 효율적입니다.
    *   **기본 성능**: 3,000 IOPS 및 125MB/s 처리량 제공.
    *   **확장 가능**: 최대 16,000 IOPS 및 1,000MB/s 처리량까지 독립적으로 확장 가능.
*   **용량**: 1GB ~ 16TB
*   **장점**: IOPS와 처리량을 독립적으로 구성할 수 있어, 필요한 성능에 정확히 맞춰 비용을 최적화할 수 있습니다.

**gp2 vs gp3 비교**

| 특징             | gp2                                     | gp3                                                   |
| :--------------- | :-------------------------------------- | :---------------------------------------------------- |
| **기본 IOPS**    | 볼륨 크기에 따라 3 IOPS/GB (최대 16,000) | 3,000 IOPS (최대 16,000 IOPS까지 독립 설정)           |
| **기본 처리량**  | 볼륨 크기에 따라 다름                     | 125MB/s (최대 1,000MB/s까지 독립 설정)              |
| **IOPS 연동**    | 볼륨 크기와 연동                           | 볼륨 크기와 독립                                      |
| **버스트 성능**  | 소형 볼륨 최대 3,000 IOPS 버스트          | 없음 (기본 성능 보장)                                 |
| **비용 효율성**  | gp3에 비해 높은 비용 가능                  | gp2에 비해 최대 20% 저렴한 비용으로 동일 성능 제공 가능 |

### 2. 프로비저닝된 IOPS SSD (Provisioned IOPS SSD): io1 & io2 Block Express

프로비저닝된 IOPS SSD 볼륨은 미션 크리티컬한 애플리케이션, 특히 지연 시간에 민감하고 일관된 고성능 IOPS가 요구되는 워크로드에 최적화되어 있습니다. EC2 인스턴스의 부트 볼륨으로 사용될 수 있습니다.

#### io1: 고성능 OLTP 애플리케이션용

*   **특징**: 매우 일관된 성능을 보장하며, 높은 IOPS를 필요로 하는 데이터베이스 워크로드에 적합합니다. IOPS를 볼륨 크기와 독립적으로 프로비저닝할 수 있습니다.
*   **최대 IOPS**: EC2 Nitro 인스턴스에서 최대 64,000 IOPS, 다른 인스턴스에서 최대 32,000 IOPS.
*   **용량**: 4GB ~ 16TB
*   **추가 기능**: EBS Multi-Attach 기능을 지원하여 여러 EC2 인스턴스에 하나의 io1 볼륨을 연결할 수 있습니다.

#### io2 Block Express: 차세대 최고 성능

*   **특징**: io1보다 더욱 향상된 성능과 내구성을 제공합니다. 서브 밀리초(sub-millisecond) 단위의 낮은 지연 시간을 자랑하며, 비즈니스상 가장 중요한 애플리케이션에 적합합니다.
*   **최대 IOPS**: 최대 256,000 IOPS.
*   **IOPS/GB 비율**: 1,000 IOPS/GB (예: 1GB 볼륨에 1,000 IOPS, 256GB 볼륨에 256,000 IOPS).
*   **용량**: 4GB ~ 64TB
*   **추가 기능**: io1과 마찬가지로 EBS Multi-Attach를 지원합니다.

io2 Block Express 볼륨은 극도의 성능이 필요한 경우 다음 스펙을 가집니다.

```
IOPS (최대): 256,000
처리량 (최대): 4,000 MB/s
지연 시간: 서브 밀리초
내구성: 99.999% (io1의 10배)
```

### 3. 처리량 최적화 HDD (Throughput Optimized HDD): st1

st1 볼륨은 대규모 순차 I/O를 처리하는 처리량 집약적인 워크로드에 최적화된 저비용 HDD 볼륨입니다. 부트 볼륨으로는 사용할 수 없습니다.

*   **특징**: 비용 효율적인 대용량 스토리지가 필요하며, 순차적 데이터 액세스가 많은 경우에 적합합니다.
*   **용도**: 빅 데이터, 데이터 웨어하우징, 로그 처리, Apache Kafka 등.
*   **성능**: 최대 500 MB/s 처리량, 최대 500 IOPS.
*   **용량**: 125GB ~ 16TB

### 4. 콜드 HDD (Cold HDD): sc1

sc1 볼륨은 가장 저렴한 비용의 HDD 볼륨으로, 자주 액세스되지 않는 데이터나 아카이브용 데이터에 적합합니다. 부트 볼륨으로는 사용할 수 없습니다.

*   **특징**: 데이터 액세스 빈도가 낮고 비용이 가장 중요한 요소일 때 선택합니다.
*   **용도**: 장기 보관용 아카이브 데이터, 백업.
*   **성능**: 최대 250 MB/s 처리량, 최대 250 IOPS.
*   **용량**: 125GB ~ 16TB

## 워크로드에 따른 EBS 볼륨 선택 전략

올바른 EBS 볼륨을 선택하기 위해서는 애플리케이션의 IOPS, 처리량, 지연 시간, 그리고 비용에 대한 요구 사항을 명확히 이해해야 합니다.

| 볼륨 타입            | 주 스토리지 유형 | 부트 볼륨 | 주요 워크로드                                        | 주요 특징 및 고려 사항                                                                                    |
| :------------------- | :--------------- | :-------- | :--------------------------------------------------- | :-------------------------------------------------------------------------------------------------------- |
| **gp2**              | SSD              | 가능      | 개발/테스트, 부트 볼륨, 소규모 데이터베이스           | IOPS가 볼륨 크기에 연동, 소형 볼륨 버스트 가능                                                            |
| **gp3**              | SSD              | 가능      | 다양한 워크로드, 부트 볼륨, 비용 최적화된 DB          | IOPS와 처리량 독립 설정 가능, gp2보다 높은 성능/비용 효율성                                               |
| **io1**              | SSD              | 가능      | 대규모 관계형/NoSQL DB, 미션 크리티컬 애플리케이션     | 일관된 고성능 IOPS, IOPS 독립 설정, EBS Multi-Attach                                                      |
| **io2 Block Express** | SSD              | 가능      | 가장 지연 시간에 민감한 대규모 데이터베이스, 엔터프라이즈 | 극도로 높은 IOPS, 서브 밀리초 지연 시간, 높은 내구성, EBS Multi-Attach, EC2 Nitro 인스턴스 필요          |
| **st1**              | HDD              | 불가능    | 빅 데이터, 데이터 웨어하우징, 로그 처리              | 처리량 집약적 워크로드에 최적화, 대규모 순차 I/O                                                          |
| **sc1**              | HDD              | 불가능    | 콜드 데이터, 아카이브, 백업                            | 가장 저렴한 비용, 자주 액세스되지 않는 데이터                                                             |

**선택을 위한 핵심 가이드라인:**

*   **범용성 및 비용 효율성**: 대부분의 경우 `gp3` 볼륨은 유연한 성능 설정과 뛰어난 비용 효율성으로 좋은 시작점이 됩니다.
*   **미션 크리티컬 데이터베이스**: 높은 IOPS와 일관된 성능이 필수적인 Oracle, SQL Server, MySQL, PostgreSQL과 같은 관계형 데이터베이스나 MongoDB와 같은 NoSQL 데이터베이스에는 `io1` 또는 `io2 Block Express`를 고려하세요. 특히 32,000 IOPS 이상의 성능이 필요하다면 EC2 Nitro 인스턴스와 `io1/io2` 조합이 필수적입니다.
*   **대규모 순차 데이터**: 빅 데이터 처리, 로그 파일 분석 등 대용량 데이터를 순차적으로 읽고 쓰는 워크로드에는 `st1`이 적합합니다.
*   **최저 비용 아카이브**: 데이터를 거의 액세스하지 않지만 장기간 보관해야 하는 경우 `sc1`을 사용하여 비용을 최소화할 수 있습니다.
*   **부트 볼륨 제한**: HDD 기반 볼륨(st1, sc1)은 EC2 인스턴스의 부트 볼륨으로 사용될 수 없다는 점을 기억해야 합니다.

## 결론

AWS EBS 볼륨 타입은 애플리케이션의 요구사항에 따라 매우 다양하게 제공됩니다. 각 볼륨 타입의 특성을 정확히 이해하고 워크로드에 가장 적합한 타입을 선택하는 것은 클라우드 인프라의 성능을 최적화하고 불필요한 비용 지출을 막는 중요한 과정입니다.

어떤 볼륨을 선택해야 할지 확신이 서지 않을 때는 항상 AWS 공식 문서를 참조하여 최신 정보와 상세한 지침을 확인하는 것이 좋습니다. 현명한 EBS 볼륨 선택을 통해 여러분의 애플리케이션이 최고의 성능을 발휘하고 비용 효율적으로 운영되기를 바랍니다!
