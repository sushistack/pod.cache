# 051. 🚀 AWS 스토리지 선택 가이드: EBS와 EFS, 무엇이 다를까?

AWS 클라우드 환경에서 애플리케이션의 성능과 가용성을 최적화하기 위해서는 올바른 스토리지 솔루션을 선택하는 것이 중요합니다. 이 글에서는 AWS에서 가장 널리 사용되는 두 가지 스토리지 서비스인 EBS(Elastic Block Store)와 EFS(Elastic File System)의 특징과 차이점을 심층적으로 분석하여, 여러분의 워크로드에 가장 적합한 스토리지를 선택할 수 있도록 돕겠습니다.

## 핵심 요약

*   **EBS**는 단일 EC2 인스턴스에 블록 수준 스토리지를 제공하며, 특정 가용 영역(AZ)에 종속됩니다.
*   **EFS**는 여러 EC2 인스턴스에 NFS(Network File System)를 통해 공유 파일 스토리지를 제공하며, 여러 AZ에 걸쳐 액세스 가능합니다.
*   두 서비스는 사용 시나리오, 성능 특성, 비용 구조에서 명확한 차이를 보이므로 워크로드 요구사항에 맞춰 선택해야 합니다.

## 1. 서론: 클라우드 스토리지, 왜 중요할까?

클라우드 컴퓨팅 환경에서 데이터 저장은 단순히 파일을 보관하는 것을 넘어, 애플리케이션의 성능, 확장성, 가용성에 직접적인 영향을 미칩니다. AWS는 다양한 스토리지 서비스를 제공하며, 그중에서도 EC2 인스턴스와 함께 주로 사용되는 EBS와 EFS는 각기 다른 목적과 특성을 가지고 있습니다. 이 둘의 차이를 명확히 이해하는 것은 아키텍처 설계의 핵심 요소입니다. 이 아티클에서는 EBS와 EFS의 주요 특징과 차이점을 자세히 살펴보고, 어떤 시나리오에서 각 서비스를 활용하는 것이 효율적인지 알아보겠습니다. 또한, 임시 스토리지인 인스턴스 스토어도 간략히 다루어 AWS 스토리지 선택에 대한 전반적인 이해를 돕겠습니다.

## 2. 본론: EBS와 EFS의 상세 분석

### 2.1. EBS (Elastic Block Store): 단일 인스턴스를 위한 블록 스토리지

EBS는 AWS EC2 인스턴스를 위한 영구적인 블록 스토리지 볼륨을 제공합니다. 이는 마치 물리 서버에 연결된 하드 드라이브와 유사하며, 운영체제나 애플리케이션에서 직접 블록 수준으로 데이터를 읽고 쓸 수 있습니다.

#### 2.1.1. EBS의 주요 특징

*   **단일 인스턴스 연결**: 기본적으로 하나의 EBS 볼륨은 한 번에 하나의 EC2 인스턴스에만 연결됩니다. (예외적으로 `io1` 및 `io2` 유형의 멀티-어태치(Multi-Attach) 기능이 있지만, 이는 특정 고가용성 시나리오에 제한적으로 사용됩니다.)
*   **가용 영역(AZ) 종속성**: EBS 볼륨은 특정 가용 영역에 잠겨 있습니다. 즉, `AZ1`에 생성된 EBS 볼륨은 `AZ2`의 EC2 인스턴스에 직접 연결할 수 없습니다.

    ```
    +-----------------+        +-----------------+
    | EC2 Instance (AZ1) | ----> | EBS Volume (AZ1) |
    +-----------------+        +-----------------+
                           |
                           X  (연결 불가)
                           |
    +-----------------+
    | EC2 Instance (AZ2) |
    +-----------------+
    ```

*   **성능 유연성**:
    *   `gp2` 볼륨 유형의 경우 디스크 크기가 증가함에 따라 IOPS(Input/Output Operations Per Second)도 함께 증가합니다.
    *   `gp3` 및 `io1` 볼륨 유형은 디스크 크기와 독립적으로 IOPS를 유연하게 조절할 수 있어, 특정 워크로드에 최적화된 성능을 제공합니다.
*   **AZ 간 마이그레이션**: EBS 볼륨을 다른 가용 영역으로 이동하려면 스냅샷 기능을 활용해야 합니다.
    1.  EBS 볼륨의 스냅샷 생성.
    2.  스냅샷을 대상 가용 영역에서 새로운 EBS 볼륨으로 복원.
*   **백업 고려 사항**: EBS 스냅샷은 백업 시 IO를 사용하므로, 애플리케이션 트래픽이 많은 시간대에는 성능 저하가 발생할 수 있습니다. 이를 방지하려면 트래픽이 적은 시간대를 이용하거나, 애플리케이션에 미치는 영향을 최소화하는 전략이 필요합니다.
*   **루트 볼륨 종료 동작**: EC2 인스턴스 종료 시, 기본적으로 루트 EBS 볼륨도 함께 종료됩니다. 그러나 이 동작은 설정에서 비활성화하여 데이터를 보존할 수 있습니다.

### 2.2. EFS (Elastic File System): 다중 인스턴스를 위한 공유 파일 시스템

EFS는 AWS에서 제공하는 완전 관리형 NFS(Network File System) 서비스입니다. 여러 EC2 인스턴스가 동시에 동일한 파일 시스템에 액세스할 수 있도록 설계되어, 분산 애플리케이션에 적합합니다.

#### 2.2.1. EFS의 주요 특징

*   **네트워크 파일 시스템**: EFS는 네트워크를 통해 접근하는 파일 시스템으로, 서버 간에 데이터를 공유하는 데 최적화되어 있습니다.
*   **다중 인스턴스 및 다중 AZ 지원**: 단일 EFS 파일 시스템은 여러 가용 영역에 걸쳐 수백 개의 EC2 인스턴스에 동시에 연결될 수 있습니다. 각 가용 영역에는 마운트 타겟(Mount Target)이 생성되어 인스턴스가 파일 시스템에 접근할 수 있게 합니다.

    ```
    +---------------------------------+
    | EFS File System (Multi-AZ)      |
    +---------------------------------+
          |        |        |
          V        V        V
    +----------+ +----------+ +----------+
    | Mount AZ1| | Mount AZ2| | Mount AZ3|
    +----------+ +----------+ +----------+
          |        |        |
          V        V        V
    +----------+ +----------+ +----------+
    | EC2 AZ1  | | EC2 AZ2  | | EC2 AZ3  |
    +----------+ +----------+ +----------+
    (여러 인스턴스가 동시 접근)
    ```

*   **Linux 인스턴스 전용**: EFS는 POSIX(Portable Operating System Interface) 파일 시스템 표준을 사용하므로, Linux 기반 EC2 인스턴스에서만 사용할 수 있습니다.
*   **비용 효율성**: EFS는 EBS보다 높은 가격대를 형성하지만, 스토리지 계층(Storage Tiers) 기능을 활용하여 비용을 절감할 수 있습니다. 예를 들어, 자주 액세스되지 않는 데이터는 Infrequent Access(IA) 스토리지 클래스로 이동시켜 비용 효율성을 높일 수 있습니다.

### 2.3. Instance Store: 임시 고성능 스토리지

EBS와 EFS 외에도 EC2 인스턴스에는 '인스턴스 스토어(Instance Store)'라는 스토리지가 있습니다. 이는 EC2 인스턴스 자체에 물리적으로 연결된 임시 스토리지입니다.

#### 2.3.1. 인스턴스 스토어의 주요 특징

*   **휘발성 데이터**: EC2 인스턴스가 종료되거나 중지되면 인스턴스 스토어에 저장된 모든 데이터는 손실됩니다.
*   **고성능**: 인스턴스에 직접 연결되어 있어 매우 낮은 지연 시간과 높은 I/O 성능을 제공합니다.
*   **사용 사례**: 임시 데이터, 캐시, 스크래치 공간 또는 복제된 데이터베이스와 같이 데이터의 영속성이 중요하지 않은 워크로드에 적합합니다.

## 3. EBS vs EFS 비교: 한눈에 보기

두 서비스의 주요 차이점을 다음 표로 요약했습니다.

| 특징          | Amazon EBS (Elastic Block Store)                       | Amazon EFS (Elastic File System)                   |
| :------------ | :----------------------------------------------------- | :------------------------------------------------- |
| **스토리지 유형** | 블록 스토리지 (Block Storage)                          | 파일 스토리지 (File Storage)                       |
| **연결 방식** | 단일 EC2 인스턴스에만 연결 (Multi-Attach 예외)           | 여러 EC2 인스턴스에 동시 연결                      |
| **가용 영역(AZ)** | 특정 AZ에 종속 (AZ 간 이동 시 스냅샷 필요)            | 여러 AZ에 걸쳐 액세스 가능 (Multi-AZ)              |
| **운영체제 지원** | Windows, Linux 등 모든 EC2 인스턴스                  | Linux EC2 인스턴스만 지원 (POSIX 호환)             |
| **확장성**      | 볼륨 증설 및 스냅샷 기반 복제                          | 온디맨드 자동 확장 (페타바이트 규모)               |
| **성능**        | IOPS 및 처리량 구성 가능 (gp3, io1 등)                 | 워크로드에 따라 자동 확장되는 성능                 |
| **주요 사용 사례** | 단일 서버 데이터베이스, OS 볼륨, 애플리케이션 로그 등 | 공유 웹 서버 (WordPress), CMS, 빅데이터 분석, 개발 환경 |
| **비용**        | 일반적으로 EFS보다 저렴                                | 일반적으로 EBS보다 비싸지만, 스토리지 계층 활용 가능 |
| **백업**        | 스냅샷을 통한 백업 및 복구                             | AWS Backup을 통한 관리형 백업                      |

## 4. 결론: 워크로드에 맞는 최적의 스토리지 선택

EBS와 EFS는 각각 고유한 강점과 사용 시나리오를 가지고 있습니다.

*   **EBS**는 단일 EC2 인스턴스에 빠르고 안정적인 블록 스토리지를 제공해야 할 때 이상적입니다. 운영체제 볼륨, 데이터베이스 스토리지, 고성능 애플리케이션의 주 스토리지 등으로 활용됩니다. 가용 영역에 종속되므로 고가용성을 위해서는 복제 전략이 필요합니다.
*   **EFS**는 여러 EC2 인스턴스가 동시에 공유 파일 시스템에 접근해야 하는 분산 환경에 최적화되어 있습니다. 웹 서버 클러스터, 콘텐츠 관리 시스템, 개발/테스트 환경 등에서 뛰어난 유연성과 확장성을 제공합니다.

AWS 클라우드 아키텍처를 설계할 때는 애플리케이션의 데이터 접근 패턴, 성능 요구사항, 가용성 목표, 그리고 예산 등을 종합적으로 고려하여 EBS와 EFS 중 가장 적합한 스토리지를 선택해야 합니다. 이 둘의 차이점을 명확히 이해하고 활용함으로써 더욱 효율적이고 견고한 클라우드 인프라를 구축할 수 있을 것입니다.
