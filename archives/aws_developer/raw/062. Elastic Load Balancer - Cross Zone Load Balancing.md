# 062. 🌐 AWS Load Balancer 크로스-존 로드 밸런싱 완전 정복

AWS 환경에서 애플리케이션의 가용성과 성능을 극대화하는 데 필수적인 로드 밸런서(Load Balancer)는 트래픽 분산의 핵심 요소입니다. 특히 여러 가용 영역(Availability Zone, AZ)에 걸쳐 인스턴스를 운영할 때, '크로스-존 로드 밸런싱(Cross-Zone Load Balancing)' 설정은 트래픽 분산 방식과 비용에 큰 영향을 미칩니다. 이 글에서는 AWS 로드 밸런서의 크로스-존 로드 밸런싱이 무엇인지, 어떤 상황에서 사용해야 하며, 각 로드 밸런서 유형별 특징과 비용 정책을 상세히 설명합니다.

**핵심 요약:**
*   크로스-존 로드 밸런싱은 여러 가용 영역에 분산된 EC2 인스턴스 전반에 걸쳐 트래픽을 균등하게 분배하는 기능입니다.
*   Application Load Balancer(ALB)는 기본 활성화이며 Inter-AZ 데이터 전송 비용이 발생하지 않지만, Network Load Balancer(NLB)와 Gateway Load Balancer(GLB)는 기본 비활성화이며 활성화 시 비용이 발생합니다.
*   애플리케이션의 특성과 비용 최적화를 고려하여 크로스-존 로드 밸런싱 활성화 여부를 신중하게 결정해야 합니다.

---

## 🚀 서론: 로드 밸런서와 가용 영역의 중요성

현대 클라우드 환경에서 안정적인 서비스를 제공하기 위해선 트래픽을 효율적으로 관리하고 잠재적인 단일 장애 지점(Single Point of Failure)을 제거하는 것이 중요합니다. AWS는 이를 위해 Elastic Load Balancing(ELB) 서비스를 제공하며, 로드 밸런서는 여러 가용 영역(AZ)에 분산된 EC2 인스턴스 간에 클라이언트 요청을 분산하여 고가용성과 확장성을 보장합니다.

이러한 다중 AZ 환경에서 로드 밸런서가 트래픽을 어떻게 분배하는지 결정하는 중요한 설정이 바로 '크로스-존 로드 밸런싱'입니다. 이 기능은 단순히 트래픽을 나누는 것을 넘어, 각 AZ 내 인스턴스의 부하 균형과 전체 시스템의 효율성에 직접적인 영향을 미칩니다.

---

## 🔄 크로스-존 로드 밸런싱 이해하기

크로스-존 로드 밸런싱은 로드 밸런서 노드(Load Balancer Node)가 트래픽을 자신의 가용 영역 내 EC2 인스턴스에만 보내는 것이 아니라, 로드 밸런서에 등록된 **모든 가용 영역의 모든 EC2 인스턴스에 걸쳐 트래픽을 균등하게 분산**시키는 기능입니다. 이 기능의 활성화 여부에 따라 트래픽 분배 방식이 크게 달라집니다.

### ⚖️ 시나리오 1: 크로스-존 로드 밸런싱 활성화 시

불균형한 상황을 예로 들어 이해해 봅시다.
두 개의 가용 영역(AZ1, AZ2)이 있고, 각각의 ALB(Application Load Balancer) 노드 뒤에 EC2 인스턴스가 연결되어 있습니다.

*   **AZ1:** 2개의 EC2 인스턴스
*   **AZ2:** 8개의 EC2 인스턴스
*   **총 EC2 인스턴스:** 10개

클라이언트가 로드 밸런서에 100%의 트래픽을 보낼 때, 로드 밸런서는 기본적으로 각 AZ에 위치한 ALB 노드로 트래픽을 50%씩 분산합니다.

**크로스-존 로드 밸런싱이 활성화된 경우:**

*   **AZ1의 ALB 노드:** 수신한 50%의 트래픽을 **모든 10개의 EC2 인스턴스**에 고르게 분산합니다 (각 EC2에 5%씩).
*   **AZ2의 ALB 노드:** 수신한 50%의 트래픽을 **모든 10개의 EC2 인스턴스**에 고르게 분산합니다 (각 EC2에 5%씩).

결과적으로, **모든 10개의 EC2 인스턴스는 각각 전체 트래픽의 10%씩을 수신**하게 됩니다 (AZ1의 ALB 노드로부터 5% + AZ2의 ALB 노드로부터 5%). 이는 각 가용 영역 내 인스턴스 수의 불균형에도 불구하고 전체 EC2 인스턴스에 트래픽이 완벽하게 균등하게 분배됨을 의미합니다.

**트래픽 분배 상세 (크로스-존 로드 밸런싱 활성화)**

| ALB 노드 (AZ) | 클라이언트 트래픽 (전체 대비) | 해당 ALB 노드 트래픽 분배 방식 | 각 EC2 인스턴스에 최종 도달 트래픽 (전체 대비) |
| :------------ | :---------------------- | :-------------------------------- | :---------------------------------------------- |
| AZ 1 (EC2 2개) | 50%                     | (50% / 10개 EC2) = 각 5%          | AZ1 EC2 (2개): 각 5% + 5% = 10%                 |
| AZ 2 (EC2 8개) | 50%                     | (50% / 10개 EC2) = 각 5%          | AZ2 EC2 (8개): 각 5% + 5% = 10%                 |
| **결과**      |                         |                                   | **모든 10개 EC2 인스턴스가 각각 전체 트래픽의 10%씩 수신** |

### ⛔ 시나리오 2: 크로스-존 로드 밸런싱 비활성화 시

동일한 불균형 예시(AZ1에 2개, AZ2에 8개의 EC2 인스턴스)를 사용합니다.

**크로스-존 로드 밸런싱이 비활성화된 경우:**

*   **AZ1의 ALB 노드:** 수신한 50%의 트래픽을 **자신의 가용 영역 내 2개의 EC2 인스턴스에만 분산**합니다 (각 EC2에 25%씩).
*   **AZ2의 ALB 노드:** 수신한 50%의 트래픽을 **자신의 가용 영역 내 8개의 EC2 인스턴스에만 분산**합니다 (각 EC2에 6.25%씩).

결과적으로, AZ1의 EC2 인스턴스들은 각각 전체 트래픽의 25%를 수신하는 반면, AZ2의 EC2 인스턴스들은 각각 전체 트래픽의 6.25%만을 수신하게 됩니다. 이는 **EC2 인스턴스 수의 불균형으로 인해 특정 AZ의 인스턴스가 과부하될 수 있음**을 의미합니다.

**트래픽 분배 상세 (크로스-존 로드 밸런싱 비활성화)**

| ALB 노드 (AZ) | 클라이언트 트래픽 (전체 대비) | 해당 ALB 노드 트래픽 분배 방식 | 각 EC2 인스턴스에 최종 도달 트래픽 (전체 대비) |
| :------------ | :---------------------- | :-------------------------------- | :---------------------------------------------- |
| AZ 1 (EC2 2개) | 50%                     | (50% / 2개 EC2) = 각 25%          | **각 25%**                                      |
| AZ 2 (EC2 8개) | 50%                     | (50% / 8개 EC2) = 각 6.25%        | **각 6.25%**                                    |
| **결과**      |                         |                                   | **AZ1 EC2는 25%, AZ2 EC2는 6.25%의 트래픽 수신 (불균형)** |

## 🛠️ 로드 밸런서 유형별 크로스-존 로드 밸런싱 동작 및 요금 정책

AWS는 여러 유형의 로드 밸런서를 제공하며, 각각의 크로스-존 로드 밸런싱 동작 및 요금 정책이 다릅니다.

### 1. Application Load Balancer (ALB)

*   **기본 설정:** **기본적으로 활성화(Enabled)** 되어 있습니다.
*   **요금 정책:** 크로스-존 로드 밸런싱으로 인해 발생하는 **Inter-AZ 데이터 전송(AZ 간 데이터 이동)에 대한 요금이 부과되지 않습니다.**
*   **제어:** ALB 자체는 항상 크로스-존 로드 밸런싱이 활성화되어 있지만, **타겟 그룹(Target Group) 수준에서 개별적으로 비활성화**할 수 있습니다. 이는 특정 마이크로 서비스나 워크로드에 대해 AZ 내 로컬리티를 유지하고자 할 때 유용합니다.

### 2. Network Load Balancer (NLB) & Gateway Load Balancer (GLB)

*   **기본 설정:** **기본적으로 비활성화(Disabled)** 되어 있습니다.
*   **요금 정책:** 크로스-존 로드 밸런싱을 **활성화하는 경우, Inter-AZ 데이터 전송에 대한 요금이 부과됩니다.** 이는 트래픽이 다른 AZ로 이동하면서 발생하는 비용입니다.
*   **제어:** 로드 밸런서 속성에서 활성화 또는 비활성화할 수 있습니다.

### 3. Classic Load Balancer (CLB)

*   **기본 설정:** **기본적으로 비활성화(Disabled)** 되어 있습니다.
*   **요금 정책:** 크로스-존 로드 밸런싱을 **활성화하더라도 Inter-AZ 데이터 전송에 대한 요금이 부과되지 않습니다.**
*   **비고:** Classic Load Balancer는 이전 세대 로드 밸런서로, **곧 단종될 예정(Deprecated)**입니다. 따라서 새로운 아키텍처에는 ALB나 NLB 사용을 권장합니다.

아래 표는 각 로드 밸런서 유형별 크로스-존 로드 밸런싱의 동작과 요금 정책을 요약한 것입니다.

**로드 밸런서 유형별 크로스-존 로드 밸런싱 요약**

| 로드 밸런서 유형 | 크로스-존 로드 밸런싱 기본 설정 | 활성화 시 Inter-AZ 데이터 전송 요금 | 비고                                                                    |
| :--------------- | :----------------------------- | :---------------------------------- | :---------------------------------------------------------------------- |
| ALB              | 활성화 (Enabled)               | 없음                                | 타겟 그룹(Target Group) 수준에서 비활성화 가능                          |
| NLB              | 비활성화 (Disabled)            | 발생                                | 활성화 시 요금 발생                                                     |
| GLB              | 비활성화 (Disabled)            | 발생                                | 활성화 시 요금 발생                                                     |
| CLB              | 비활성화 (Disabled)            | 없음                                | 곧 단종될 예정 (Deprecated), 새로운 환경에서는 사용 지양                  |

## ✅ 왜 중요한가? 유스케이스 및 고려사항

크로스-존 로드 밸런싱은 '옳고 그름'의 문제가 아니라, 애플리케이션의 특정 요구사항에 따라 최적의 선택이 달라지는 설정입니다.

### 크로스-존 로드 밸런싱 활성화의 장점

*   **균등한 부하 분산:** 가용 영역별 EC2 인스턴스 수의 불균형이 있더라도 모든 인스턴스에 트래픽이 고르게 분산되어 자원 활용률을 최적화하고 특정 인스턴스 과부하를 방지합니다.
*   **간소화된 스케일링:** 각 AZ 내 인스턴스 수에 신경 쓰지 않고 전체적으로 인스턴스를 확장하거나 축소할 수 있어 운영 복잡성을 줄입니다.
*   **향상된 탄력성:** 특정 AZ에 문제가 발생해도 다른 AZ의 인스턴스가 트래픽을 처리할 수 있는 유연성을 제공합니다.

### 크로스-존 로드 밸런싱 비활성화의 장점 (NLB/GLB에 해당)

*   **데이터 로컬리티 유지:** 특정 워크로드(예: 캐시, 세션 스토리지)의 경우, 데이터가 해당 AZ 내에 유지되는 것이 성능상 이점이나 비용 효율적일 수 있습니다.
*   **비용 통제:** NLB 및 GLB의 경우, 활성화 시 Inter-AZ 데이터 전송 요금이 발생하므로, 이를 비활성화하여 비용을 절감할 수 있습니다.
*   **특정 아키텍처 요구사항:** 드물지만, 특정 네트워크 아키텍처나 보안 요구사항 때문에 트래픽을 AZ 내에 격리해야 하는 경우가 있을 수 있습니다.

## 💡 결론: 현명한 선택을 위한 가이드

AWS 로드 밸런서의 크로스-존 로드 밸런싱은 서비스의 성능, 가용성, 그리고 비용에 직접적인 영향을 미치는 중요한 설정입니다.

*   대부분의 웹 애플리케이션 및 마이크로 서비스에는 **ALB의 기본 활성화 설정을 유지**하여 균등한 부하 분산과 비용 효율성을 확보하는 것이 좋습니다.
*   **NLB나 GLB**를 사용하는 경우, **Inter-AZ 데이터 전송 요금**을 인지하고 애플리케이션의 특성(예: 극도의 저지연 요구사항, 데이터 로컬리티 선호)과 비용 효율성을 종합적으로 고려하여 활성화 여부를 결정해야 합니다.

각 로드 밸런서 유형의 기본 동작과 요금 정책을 정확히 이해하고, 여러분의 애플리케이션 요구사항에 맞춰 최적의 설정을 선택하는 것이 클라우드 아키텍처를 성공적으로 구축하는 핵심 요소가 될 것입니다.
