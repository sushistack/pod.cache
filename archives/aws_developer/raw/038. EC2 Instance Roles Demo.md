# 038. 🛡️ EC2 인스턴스를 위한 IAM 역할: 자격 증명 관리의 모범 사례

EC2 인스턴스에 AWS 리소스 접근 권한을 부여하는 가장 안전한 방법은 IAM 역할을 활용하는 것입니다. 직접 Access Key와 Secret Access Key를 인스턴스에 저장하는 것은 심각한 보안 위험을 초래합니다. 이 아티클에서는 IAM 역할의 중요성과 EC2 인스턴스에 적용하는 실습 과정을 통해 안전한 클라우드 보안 모범 사례를 제시합니다.

---

## 서론: 클라우드 시대의 보안, 자격 증명 관리의 중요성

클라우드 환경에서 애플리케이션을 운영할 때, AWS EC2 인스턴스가 다른 AWS 서비스(S3, DynamoDB, IAM 등)와 안전하게 통신하고 상호 작용하는 것은 필수적입니다. 이때 EC2 인스턴스에 해당 서비스에 접근할 수 있는 권한을 부여해야 하는데, 이 과정을 어떻게 수행하느냐에 따라 시스템의 보안 수준이 크게 달라집니다. 본 아티클에서는 AWS Identity and Access Management(IAM) 역할을 활용하여 EC2 인스턴스에 안전하게 권한을 부여하는 방법을 심층적으로 다루고, 잘못된 자격 증명 관리 방식이 초래할 수 있는 위험성에 대해 경고합니다.

## 본론: IAM 역할 기반의 안전한 권한 관리

### EC2 인스턴스에서 AWS CLI 사용하기

먼저 EC2 인스턴스에 접속하여 AWS CLI 명령어를 사용해 보겠습니다. EC2 인스턴스에 접속하는 방법은 SSH 클라이언트 또는 AWS EC2 Instance Connect 등 다양합니다. 여기서는 EC2 Instance Connect를 사용하겠습니다.

인스턴스에 접속 후, AWS IAM 사용자 목록을 조회하는 명령어를 실행합니다.

```bash
aws iam list-users
```

아직 EC2 인스턴스에 AWS 자격 증명이 설정되지 않았기 때문에, 다음과 같은 에러 메시지가 출력될 것입니다.

```
Unable to locate credentials. You can configure credentials by using "aws configure".
```

이 메시지는 현재 인스턴스가 AWS API 호출을 위한 인증 정보를 찾을 수 없음을 의미합니다.

### 🚨 AWS 자격 증명 직접 설정의 위험성

에러 메시지에 제시된 `aws configure` 명령어를 사용하면 Access Key ID와 Secret Access Key, 리전 등을 직접 입력하여 자격 증명을 설정할 수 있습니다.

```bash
aws configure
AWS Access Key ID [None]: YOUR_ACCESS_KEY_ID
AWS Secret Access Key [None]: YOUR_SECRET_ACCESS_KEY
Default region name [None]: ap-northeast-2
Default output format [None]: json
```

**하지만 이는 절대 해서는 안 되는 매우 위험한 방식입니다.**

개인의 AWS Access Key ID와 Secret Access Key를 EC2 인스턴스에 직접 설정하고 저장하는 것은 다음과 같은 심각한 보안 문제를 야기합니다.

*   **자격 증명 노출 위험**: 인스턴스에 접근 권한이 있는 누구든지 해당 자격 증명을 탈취할 수 있습니다. 이는 인스턴스가 해킹당하거나, 공유된 환경에서 다른 사용자가 접근할 경우 치명적입니다.
*   **권한 과다 부여**: 일반적으로 사용자의 Access Key는 넓은 권한을 가지는 경우가 많습니다. 인스턴스에 이를 저장하면, 인스턴스 자체에 불필요하게 넓은 권한이 부여되어 보안 취약점이 될 수 있습니다.
*   **자격 증명 수명 주기 관리의 어려움**: 직접 설정된 자격 증명은 정기적으로 교체하고 관리하기 어렵습니다.

**핵심 권고 사항:** EC2 인스턴스에 절대 IAM 사용자 API 키(Access Key ID 및 Secret Access Key)를 직접 입력하거나 저장하지 마십시오.

### IAM 역할로 EC2 권한 부여하기: 모범 사례

AWS에서는 EC2 인스턴스에 안전하게 권한을 부여하기 위해 IAM 역할을 사용할 것을 강력히 권고합니다. IAM 역할은 AWS 서비스(EC2, Lambda 등) 또는 AWS 계정의 사용자에게 일시적인 권한을 위임하는 메커니즘입니다.

#### 1. IAM 역할 생성 및 정책 연결 (사전 준비)

먼저 EC2 인스턴스에 연결할 IAM 역할이 필요합니다. 이 역할은 EC2 서비스가 신뢰할 수 있도록 구성되어야 하며, 필요한 AWS 리소스에 대한 접근 권한을 정의하는 정책이 연결되어 있어야 합니다.

예를 들어, IAM 사용자 목록을 조회하는 권한만 부여하려면 `IAMReadOnlyAccess` 정책이 연결된 역할을 생성해야 합니다. 이 아티클에서는 `DemoRoleForEC2`라는 역할이 `IAMReadOnlyAccess` 정책과 연결되어 있다고 가정합니다.

#### 2. EC2 인스턴스에 IAM 역할 연결하기

생성된 IAM 역할을 EC2 인스턴스에 연결하는 단계는 다음과 같습니다.

1.  AWS Management Console에서 EC2 서비스로 이동합니다.
2.  대상 EC2 인스턴스를 선택합니다.
3.  상단의 `작업(Actions)` 드롭다운 메뉴를 클릭합니다.
4.  `보안(Security)` -> `IAM 역할 수정(Modify IAM role)`을 선택합니다.
5.  드롭다운 메뉴에서 미리 생성해 둔 `DemoRoleForEC2` (또는 해당 역할)를 선택합니다.
6.  `저장(Save)` 버튼을 클릭하여 변경 사항을 적용합니다.

이제 EC2 인스턴스의 `세부 정보(Details)` 탭이나 `보안(Security)` 탭에서 IAM 역할이 `DemoRoleForEC2`로 설정되었음을 확인할 수 있습니다.

#### 3. IAM 역할 적용 확인 및 권한 테스트

IAM 역할이 인스턴스에 연결된 후, 다시 EC2 인스턴스 터미널로 돌아가 `aws iam list-users` 명령어를 실행해 보세요.

```bash
aws iam list-users
```

이번에는 `Unable to locate credentials` 에러 대신, 계정의 IAM 사용자 목록이 JSON 형식으로 출력될 것입니다. 이는 EC2 인스턴스가 IAM 역할을 통해 임시 자격 증명을 자동으로 획득하고, `IAMReadOnlyAccess` 정책에 의해 부여된 권한으로 `list-users` API 호출에 성공했음을 의미합니다.

```json
{
    "Users": [
        {
            "Path": "/",
            "UserName": "test-user-1",
            "UserId": "AID************D",
            "Arn": "arn:aws:iam::123456789012:user/test-user-1",
            "CreateDate": "2023-01-01T00:00:00Z"
        },
        {
            "Path": "/",
            "UserName": "another-user",
            "UserId": "AID************B",
            "Arn": "arn:aws:iam::123456789012:user/another-user",
            "CreateDate": "2023-02-01T00:00:00Z"
        }
    ]
}
```
(위 출력은 예시이며, 실제 출력은 계정에 따라 다를 수 있습니다.)

#### 4. 역할 권한 변경의 즉각적인 효과 (실험)

IAM 역할의 또 다른 장점은 권한 변경이 즉각적으로 반영된다는 것입니다. 인스턴스를 재부팅할 필요 없이, 역할에 연결된 정책만 수정하면 됩니다.

1.  AWS Management Console에서 IAM 서비스로 이동합니다.
2.  `역할(Roles)` 메뉴에서 `DemoRoleForEC2`를 선택합니다.
3.  현재 연결된 `IAMReadOnlyAccess` 정책을 `분리(Detach)`합니다.
4.  EC2 인스턴스 터미널로 돌아가 다시 `aws iam list-users` 명령어를 실행합니다.

명령어를 실행하면 `AccessDenied` 메시지가 출력될 것입니다. 이는 역할에서 권한이 제거되었기 때문입니다.

```json
{
    "Error": {
        "Code": "AccessDenied",
        "Message": "You are not authorized to perform this operation."
    }
}
```

이제 `IAMReadOnlyAccess` 정책을 다시 역할에 연결하고, 몇 초에서 몇 분 정도의 전파(propagation) 시간을 기다린 후 `aws iam list-users` 명령어를 재실행하면 다시 정상적인 사용자 목록을 확인할 수 있습니다. 이는 IAM 역할이 얼마나 유연하고 동적으로 권한을 관리할 수 있는지 보여줍니다.

## 결론: IAM 역할은 EC2 보안의 핵심

EC2 인스턴스에 AWS 리소스 접근 권한을 부여하는 유일하고 가장 안전한 방법은 IAM 역할을 사용하는 것입니다. IAM 역할은 일시적인 자격 증명을 제공하고, Access Key 노출 위험을 제거하며, 권한 변경을 신속하게 적용할 수 있도록 합니다.

보안은 클라우드 환경에서 가장 중요한 고려 사항이며, IAM 역할은 이러한 보안을 달성하기 위한 기본적이면서도 강력한 도구입니다. 항상 이 모범 사례를 따르고, 어떠한 경우에도 민감한 자격 증명을 인스턴스에 직접 저장하는 실수를 저지르지 않기를 바랍니다.
