# 025. 🔒 클라우드 보안, AWS 공유 책임 모델 완벽 이해하기

클라우드 환경에서 보안 책임은 AWS와 사용자 간에 명확히 구분되는 '공유 책임 모델'을 따릅니다.
AWS는 '클라우드 자체의 보안'을 책임지며, 인프라, 네트워크, 물리적 보안 등을 관리합니다.
사용자는 '클라우드 내의 보안'을 책임지며, 데이터, 계정 관리(IAM), 네트워크 설정, 애플리케이션 보안 등에 대한 역할을 수행해야 합니다.

## 서론

클라우드 컴퓨팅 환경으로의 전환은 많은 기업에게 민첩성과 확장성을 제공했지만, 동시에 보안 책임에 대한 새로운 질문을 던졌습니다. 특히 AWS와 같은 클라우드 서비스 제공업체(CSP)를 사용할 때, "누가 무엇을 책임지는가?"라는 질문은 매우 중요합니다. 이 질문에 대한 답이 바로 **AWS 공유 책임 모델(Shared Responsibility Model)**입니다. 이 모델을 명확히 이해하는 것은 클라우드 환경에서 안전하고 효율적인 운영을 위한 첫걸음입니다.

## 공유 책임 모델이란?

AWS 공유 책임 모델은 클라우드 환경에서의 보안 및 규정 준수 책임을 AWS와 고객(사용자) 간에 명확하게 구분하는 프레임워크입니다. 이는 AWS가 제공하는 서비스 모델(IaaS, PaaS, SaaS)에 따라 책임의 범위가 달라지지만, 기본 원칙은 동일합니다. 쉽게 말해, AWS는 '클라우드 자체의 보안(Security *of* the Cloud)'을 책임지고, 고객은 '클라우드 내의 보안(Security *in* the Cloud)'을 책임집니다.

## AWS의 책임: 클라우드 '자체의 보안' (Security *of* the Cloud)

AWS는 클라우드 서비스를 구성하는 인프라의 보안을 책임집니다. 이는 고객이 직접 접근하거나 관리할 수 없는 영역으로, AWS가 전적으로 관리합니다.

AWS의 주요 책임 영역은 다음과 같습니다:

*   **인프라 보안:** AWS는 서비스가 실행되는 하드웨어, 소프트웨어, 네트워크, 그리고 시설(데이터 센터)의 물리적 보안을 담당합니다.
*   **글로벌 네트워크 보안:** AWS 네트워크의 모든 구성 요소와 연결성을 안전하게 유지하며, DDoS 공격 방어 등의 네트워크 보안을 제공합니다.
*   **서비스 구성 및 취약점 분석:** AWS가 제공하는 서비스 자체의 보안 구성 및 알려진 취약점에 대한 분석 및 패치를 수행합니다.
*   **규정 준수:** AWS 자체의 글로벌 및 산업별 규정 준수(예: ISO 27001, SOC 1/2/3, PCI DSS 등)를 관리합니다.

이러한 책임은 AWS가 '클라우드를 안전하게 운영'하는 것을 보장합니다.

## 사용자의 책임: 클라우드 '내 보안' (Security *in* the Cloud)

반면, 사용자는 AWS가 제공하는 클라우드 인프라 위에서 자신의 데이터를 보호하고 서비스를 안전하게 구성 및 운영하는 책임을 가집니다. 이는 사용자가 선택하는 서비스 모델에 따라 책임의 깊이가 달라집니다.

### IAM (Identity and Access Management) 사례로 본 사용자 책임

AWS의 핵심 보안 서비스 중 하나인 IAM (Identity and Access Management)을 통해 사용자 책임을 구체적으로 살펴보겠습니다. IAM은 사용자, 그룹, 역할에 대한 접근 권한을 관리하는 서비스입니다. AWS는 IAM 서비스 자체의 보안을 담당하지만, IAM을 '어떻게' 사용하는지는 전적으로 사용자의 책임입니다.

사용자의 주요 책임 영역은 다음과 같습니다:

*   **사용자, 그룹, 역할, 정책 생성 및 관리:**
    *   사용자는 적절한 권한을 가진 사용자, 그룹, 역할을 생성하고, 이들에게 필요한 정책을 할당하고 관리해야 합니다. 최소 권한 원칙(Least Privilege Principle)을 준수하는 것이 중요합니다.
    ```json
    {
        "Version": "2012-10-17",
        "Statement": [
            {
                "Effect": "Allow",
                "Action": [
                    "s3:GetObject",
                    "s3:ListBucket"
                ],
                "Resource": [
                    "arn:aws:s3:::my-secure-bucket",
                    "arn:aws:s3:::my-secure-bucket/*"
                ]
            }
        ]
    }
    ```
    *   위 예시는 `my-secure-bucket`에 대한 읽기 권한만을 부여하는 IAM 정책으로, 불필요한 접근을 방지하는 최소 권한 원칙을 보여줍니다.
*   **다단계 인증(MFA) 활성화 및 강제:**
    *   모든 계정, 특히 루트 계정에 MFA를 활성화하고 강제 적용하는 것은 계정 보안을 위한 가장 기본적인 책임입니다.
*   **접근 키(Access Key) 로테이션:**
    *   장기적으로 사용되는 접근 키(Access Key)는 주기적으로 로테이션하여 키 유출 시 발생할 수 있는 보안 위험을 줄여야 합니다.
*   **접근 패턴 분석 및 권한 검토:**
    *   IAM 도구를 활용하여 접근 패턴을 지속적으로 분석하고, 할당된 권한이 여전히 적절한지 주기적으로 검토해야 합니다. 불필요하거나 과도한 권한은 즉시 제거해야 합니다.

### AWS 공유 책임 모델 요약

다음 표는 AWS와 사용자 간의 책임을 간략하게 요약한 것입니다.

| 책임 영역          | AWS의 책임 (Security *of* the Cloud)                                   | 사용자의 책임 (Security *in* the Cloud)                                |
| :----------------- | :--------------------------------------------------------------------- | :------------------------------------------------------------------- |
| **인프라**         | 컴퓨팅, 스토리지, 데이터베이스, 네트워킹을 제공하는 물리적 시설 및 하드웨어 | 운영 체제, 네트워크 설정, 방화벽 구성                                  |
| **데이터**         | 없음                                                                   | 저장된 데이터의 암호화, 보안 구성, 무결성 관리                         |
| **계정 및 접근 관리** | IAM 서비스 자체의 보안                                                 | 사용자, 그룹, 역할 생성 및 정책 관리, MFA 활성화, 접근 키 로테이션 |
| **네트워크 구성**  | 글로벌 네트워크 인프라 보안                                            | 가상 프라이빗 클라우드(VPC), 보안 그룹, 네트워크 ACL 구성             |
| **애플리케이션**   | 없음                                                                   | 고객 애플리케이션의 보안 코드 작성, 패치, 취약점 관리                  |
| **운영 체제/런타임** | 관리형 서비스(예: Fargate)의 OS 패치                                   | EC2 인스턴스의 OS 패치, 미들웨어, 애플리케이션 관리                      |

## 결론

AWS 공유 책임 모델은 클라우드 환경에서 보안의 핵심 원칙입니다. AWS는 강력한 글로벌 인프라와 서비스 보안을 제공하지만, 그 위에 구축되는 모든 것에 대한 최종적인 책임은 사용자에게 있습니다. 이 모델을 정확히 이해하고 자신의 역할을 충실히 이행함으로써, 개발자와 기업은 클라우드의 이점을 최대한 활용하면서도 보안 위협으로부터 안전한 환경을 구축할 수 있을 것입니다. 보안은 한 번의 설정으로 끝나는 것이 아니라, 지속적인 관심과 관리가 필요한 여정임을 잊지 말아야 합니다.
