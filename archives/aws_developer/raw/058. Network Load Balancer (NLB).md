# 058. 🚀 AWS Network Load Balancer: 초고성능 L4 로드 밸런싱 핵심 이해

AWS 환경에서 고성능과 낮은 지연 시간을 요구하는 애플리케이션을 운영하고 계신가요? Network Load Balancer(NLB)는 전송 계층(Layer 4)에서 TCP 및 UDP 트래픽을 효율적으로 분산하며, 초당 수백만 건의 요청을 처리할 수 있는 뛰어난 성능을 제공합니다. 이 아티클에서는 NLB의 주요 특징과 활용 방법을 심층적으로 살펴보겠습니다.

## 서론

클라우드 환경에서 애플리케이션의 가용성과 확장성을 확보하는 데 로드 밸런서는 필수적인 요소입니다. AWS는 다양한 유형의 로드 밸런서를 제공하며, 그중 Network Load Balancer(NLB)는 특히 TCP/UDP 기반의 초고성능 워크로드에 최적화되어 있습니다. Layer 4에서 작동하는 NLB는 특정 유형의 트래픽 처리와 고정 IP 주소 요구사항을 충족시키는 데 중요한 역할을 합니다.

## 본론

### 1. Network Load Balancer의 핵심 특징

Network Load Balancer는 다음과 같은 독점적인 특징들로 인해 특정 사용 사례에서 독보적인 선택지로 자리매김합니다.

#### 가. 전송 계층(Layer 4) 로드 밸런싱

NLB는 OSI 모델의 전송 계층(Layer 4)에서 작동하며, 주로 **TCP(Transmission Control Protocol)** 및 **UDP(User Datagram Protocol)** 트래픽을 처리합니다. 이는 HTTP/HTTPS와 같은 애플리케이션 계층(Layer 7) 트래픽을 처리하는 Application Load Balancer(ALB)와 차별화되는 지점입니다.

*   **TCP**: 연결 지향 프로토콜로, 신뢰할 수 있는 데이터 전송이 필요한 서비스에 적합합니다. (예: 데이터베이스, 게임 서버 일부)
*   **UDP**: 비연결형 프로토콜로, 실시간 스트리밍, DNS 쿼리, 온라인 게임 등 빠른 전송과 낮은 오버헤드가 중요한 서비스에 활용됩니다.

시험에서 `UDP` 또는 `TCP` 트래픽 처리가 언급된다면, Network Load Balancer를 고려해야 합니다.

#### 나. 초고성능 및 초저지연

NLB는 "극단적인 성능(extreme performance)"에 초점을 맞춰 설계되었습니다.

*   **초당 수백만 건의 요청 처리**: 대규모 트래픽을 처리해야 하는 환경에 이상적입니다.
*   **초저지연(Ultra Low Latency)**: 실시간 서비스나 높은 처리량이 요구되는 애플리케이션에 최소한의 지연 시간을 보장합니다.

#### 다. 가용성 영역당 고정 IP 주소

NLB의 가장 독특한 특징 중 하나는 각 가용성 영역(Availability Zone, AZ)마다 하나의 **고정 IP 주소**를 제공한다는 점입니다. 필요에 따라 이러한 고정 IP 주소에 `Elastic IP`를 할당할 수 있습니다.

이 기능은 다음과 같은 상황에서 매우 유용합니다.
*   애플리케이션에 **고정된 외부 IP 주소** 세트를 노출해야 하는 경우 (예: 특정 IP 주소만 허용하는 방화벽 규칙 설정)
*   일관된 엔드포인트가 필요한 레거시 시스템과의 연동

만약 여러분의 애플리케이션이 1개, 2개 또는 3개의 특정 IP 주소를 통해서만 액세스되어야 한다는 요구사항이 있다면, NLB가 적절한 선택지입니다.

### 2. Network Load Balancer의 타겟 그룹

NLB는 Application Load Balancer와 유사하게 **타겟 그룹(Target Group)**을 사용하여 트래픽을 백엔드 리소스로 라우팅합니다. NLB 타겟 그룹에 등록할 수 있는 대상은 다음과 같습니다.

#### 가. EC2 인스턴스

가장 일반적인 형태의 타겟 그룹입니다. NLB는 EC2 인스턴스로 TCP 또는 UDP 트래픽을 직접 전달합니다.

#### 나. IP 주소

NLB 타겟 그룹에 특정 **IP 주소**를 직접 등록할 수 있습니다. 이때 등록되는 IP 주소는 **사설 IP(Private IP)**여야 합니다. 이 기능은 매우 유연한 아키텍처를 가능하게 합니다.

*   **소유한 EC2 인스턴스의 사설 IP**: 특정 EC2 인스턴스를 지정하여 트래픽을 보내고 싶을 때 사용합니다.
*   **온프레미스 데이터센터 서버의 사설 IP**: AWS Direct Connect나 VPN을 통해 연결된 온프레미스 데이터센터 내의 서버 IP 주소를 등록하여, 클라우드와 온프레미스 환경을 아우르는 하이브리드 로드 밸런싱을 구현할 수 있습니다.

#### 다. Application Load Balancer (ALB)

흥미롭게도 NLB는 **Application Load Balancer(ALB)**를 타겟으로 가질 수 있습니다. 이러한 조합은 다음과 같은 시나리오에서 강력한 이점을 제공합니다.

| 계층 | 역할 (주요 이점) |
|---|---|
| **NLB (Front-end)** | - 고정 IP 주소 제공 <br> - 초고성능, 초저지연 <br> - TCP/UDP 트래픽 처리 |
| **ALB (Back-end)** | - HTTP/HTTPS 규칙 기반 라우팅 <br> - 경로 기반, 호스트 기반 라우팅 <br> - 고급 보안 기능 (WAF 연동 등) |

NLB를 ALB 앞에 배치함으로써, 고정 IP 주소의 이점을 유지하면서 ALB의 풍부한 HTTP/HTTPS 라우팅 규칙과 고급 기능을 활용할 수 있게 됩니다.

### 3. 헬스 체크 프로토콜 지원

NLB의 타겟 그룹 헬스 체크는 백엔드 인스턴스의 상태를 확인하기 위해 세 가지 프로토콜을 지원합니다.

*   `TCP`
*   `HTTP`
*   `HTTPS`

만약 백엔드 애플리케이션이 `HTTP` 또는 `HTTPS` 프로토콜을 사용하여 상태 정보를 제공한다면, 해당 프로토콜로 헬스 체크를 정의하여 보다 정교한 상태 모니터링이 가능합니다.

## 결론

AWS Network Load Balancer는 TCP 및 UDP 기반의 고성능 애플리케이션에 최적화된 로드 밸런싱 솔루션입니다. Layer 4에서의 작동, 초고성능, 고정 IP 주소 제공, 그리고 유연한 타겟 그룹 지원은 NLB를 특정 워크로드에 필수적인 요소로 만듭니다. 고정 IP가 필요하거나, 초당 수백만 건의 요청을 처리해야 하거나, TCP/UDP 트래픽 분산이 핵심이라면 NLB는 여러분의 아키텍처에 강력한 안정성과 성능을 제공할 것입니다. 이 글을 통해 NLB의 핵심을 이해하고 여러분의 AWS 아키텍처 설계에 도움이 되기를 바랍니다.
