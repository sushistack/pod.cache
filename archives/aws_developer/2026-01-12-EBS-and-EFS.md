## 2026-01-12 EBS와 EFS, 무엇이 다를까?


<details>
<summary>복습 키워드: EBS, EFS, Instance Store의 차이와 활용</summary>


* **EBS**는 단일 EC2 인스턴스에 블록 수준 스토리지를 제공하며, 특정 가용 영역(AZ)에 종속됩니다.
* **EFS**는 여러 EC2 인스턴스에 NFS(Network File System)를 통해 공유 파일 스토리지를 제공하며, 여러 AZ에 걸쳐 액세스 가능합니다.
* 두 서비스는 사용 시나리오, 성능 특성, 비용 구조에서 명확한 차이를 보이므로 워크로드 요구사항에 맞춰 선택해야 합니다.

### EBS (Elastic Block Store): 단일 인스턴스를 위한 블록 스토리지

EBS는 AWS EC2 인스턴스를 위한 영구적인 블록 스토리지 볼륨을 제공합니다. 이는 마치 물리 서버에 연결된 하드 드라이브와 유사하며, 운영체제나 애플리케이션에서 직접 블록 수준으로 데이터를 읽고 쓸 수 있습니다.

#### 특징

- 단일 인스턴스 연결: 기본적으로 하나의 EBS 볼륨은 한 번에 하나의 EC2 인스턴스에만 연결됩니다. (예외적으로 `io1` 및 `io2` 유형의 Multi-Attach 기능)
- 가용 영역(AZ) 종속성: EBS 볼륨은 특정 가용 영역에 잠겨 있습니다.
- 성능 유연성: 
    - gp2: 디스크 크기가 증가함에 따라 IOPS도 함께 증가합니다.
    - gp3, io1: 디스크 크기와 독립적으로 IOPS를 유연하게 조절할 수 있어, 특정 워크로드에 최적화된 성능을 제공합니다.
- AZ 간 마이그레이션:
    1. EBS 볼륨의 스냅샷 생성.
    2. 스냅샷을 대상 가용 영역에서 새로운 EBS 볼륨으로 복원. 
    - 백업 고려 사항: EBS 스냅샷은 백업 시 IO를 사용하므로, 애플리케이션 트래픽이 많은 시간대에는 성능 저하가 발생할 수 있습니다.
- 루트 볼륨 종료 동작: EC2 인스턴스 종료 시, 기본적으로 루트 EBS 볼륨도 함께 종료됩니다.

### EFS (Elastic File System): 다중 인스턴스를 위한 공유 파일 시스템

EBS는 AWS EC2 인스턴스를 위한 영구적인 블록 스토리지 볼륨을 제공합니다. 이는 마치 물리 서버에 연결된 하드 드라이브와 유사하며, 운영체제나 애플리케이션에서 직접 블록 수준으로 데이터를 읽고 쓸 수 있습니다.

#### 특징

- 네트워크 파일 시스템: EFS는 네트워크를 통해 접근하는 파일 시스템으로, 서버 간에 데이터를 **공유**하는 데 최적화되어 있습니다.
- 다중 인스턴스 및 다중 AZ 지원: 단일 EFS 파일 시스템은 여러 가용 영역에 걸쳐 수백 개의 EC2 인스턴스에 동시에 연결될 수 있습니다.
- Linux 인스턴스 전용: EFS는 POSIX 파일 시스템 표준을 사용하므로, Linux 기반 EC2 인스턴스에서만 사용할 수 있습니다.
- 비용 효율성: EFS는 EBS보다 높은 가격대를 형성하지만, 스토리지 계층(Storage Tiers) 기능을 활용하여 비용을 절감할 수 있습니다. 

### Instance Store: 임시 고성능 스토리지

EBS와 EFS 외에도 EC2 인스턴스에는 '인스턴스 스토어(Instance Store)'라는 스토리지가 있습니다. 이는 EC2 인스턴스 자체에 물리적으로 연결된 임시 스토리지입니다.

#### 특징

- **휘발성 데이터**: EC2 인스턴스가 종료되거나 중지되면 인스턴스 스토어에 저장된 모든 데이터는 손실됩니다.
- **고성능**: 인스턴스에 직접 연결되어 있어 매우 낮은 지연 시간과 높은 I/O 성능을 제공합니다.
- **사용 사례**: 임시 데이터, 캐시, 스크래치 공간 또는 복제된 데이터베이스와 같이 데이터의 영속성이 중요하지 않은 워크로드에 적합합니다.

### EBS vs EFS 비교: 한눈에 보기

두 서비스의 주요 차이점을 다음 표로 요약했습니다.

| 특징 | Amazon EBS (Elastic Block Store) | Amazon EFS (Elastic File System) |
| :--- | :------ | :------ |
| **스토리지 유형** | 블록 스토리지 (Block Storage) | 파일 스토리지 (File Storage) |
| **연결 방식** | 단일 EC2 인스턴스에만 연결 (Multi-Attach 예외) | 여러 EC2 인스턴스에 동시 연결 |
| **가용 영역(AZ)** | 특정 AZ에 종속 (AZ 간 이동 시 스냅샷 필요) | 여러 AZ에 걸쳐 액세스 가능 (Multi-AZ) |
| **운영체제 지원** | Windows, Linux 등 모든 EC2 인스턴스 | Linux EC2 인스턴스만 지원 (POSIX 호환) |
| **확장성**      | 볼륨 증설 및 스냅샷 기반 복제 | 온디맨드 자동 확장 (페타바이트 규모) |
| **성능**        | IOPS 및 처리량 구성 가능 (gp3, io1 등) | 워크로드에 따라 자동 확장되는 성능 |
| **주요 사용 사례** | 단일 서버 데이터베이스, OS 볼륨, 애플리케이션 로그 등 | 공유 웹 서버 (WordPress), CMS, 빅데이터 분석, 개발 환경 |
| **비용**        | 일반적으로 EFS보다 저렴 | 일반적으로 EBS보다 비싸지만, 스토리지 계층 활용 가능 |
| **백업**        | 스냅샷을 통한 백업 및 복구 | AWS Backup을 통한 관리형 백업 |
